# 管理画面の使い方

管理画面で「どこを開き、何を確認してから保存するか」をまとめています。サーバーの停止・更新・バックアップは[運用手順](operations.md)、認証の詳しい条件は[管理認証・権限・CAP](features/administration.md)を参照してください。

## やりたいことから探す

| やりたいこと | 開く画面・手順 |
| --- | --- |
| サイト名・板・カテゴリーを変更する | サイト設定・板の管理・板カテゴリー |
| ログイン・再認証の期限が切れた | [ログインと再認証](#ログインと再認証) |
| 日付や期間を簡単に指定したい | [日時・期限の入力](features/administration.md#日時期限の入力) |
| 認証方法を登録・変更する | パスキー。[登録とログイン方法](features/administration.md#ログイン方法) |
| 管理を他の人に任せる | 管理者。[ロール・担当板・追加権限](admin-permissions.md) |
| 閲覧できる人やクローラーを制限する | [閲覧制限と管理用アクセスの違い](#閲覧制限と管理用アクセスの違い) |
| 回線の誤判定・更新状況を調べる | [回線分類](#回線分類を確認する) |
| 誰が何を変更したか調べる | [管理操作の記録](#管理操作の記録を調べる) |
| レス削除・投稿者規制・スレッド停止を行う | [レスとスレッドの管理](#レスとスレッドを管理する) |
| 削除依頼に回答する・送信間隔を変える | [削除依頼への対応](#削除依頼に対応する) |
| 通報による自動停止を確認する | 自動停止・通報 |
| 帯域・整理・通報条件を変える | 運用設定。[設定場所と反映時点](configuration.md#どこで設定しいつ反映するか) |
| 掲示板ソフトウェアを更新する | サイト管理者の「ソフトウェア更新」。[更新と再起動の確認](software-updates.md) |
| 保存容量や回収状況を確認する | 保存の整理。[容量の確認手順](operations.md#保存容量を確認する) |
| 原本を照会・保全・出力する | [提出用ログ](#提出用ログを取得する)。[非公開記録の権限](admin-permissions.md#追加権限を選ぶ) |
| 画面を開けない・応答が遅い | [状態ごとの確認先](#画面を開けない保存できないとき)・[応答待ちの切り分け](operations.md#管理画面の応答待ちを調べる) |

表の画面名は、管理メニューの表示に合わせています。画面内の「マニュアル」も利用できます。

## 最初に確認すること

設定した `admin.origin` を開いてログインします。通常は掲示板と同じHTTPSの `/admin/` です。接続先が分からない場合は[管理画面の公開設定](setup.md#管理画面を同じポートで公開する)を確認してください。

操作できる範囲は、ログインした管理者のロール・担当板・追加権限で決まります。メニューにない画面は、URLを直接開いても操作できません。再認証は本人の確認であり、権限を増やす手続きではありません。

## ログインと再認証

ログイン方法は、自分に登録された認証手段とログイン制限で決まります。

| 方法 | 入力・操作 |
| --- | --- |
| パスキー | ログイン名の入力は不要。「パスキーでログイン」から端末上でアカウントを選ぶ |
| パスワード | ログイン名とパスワードを入力する |
| パスワード＋OTP | ログイン名・パスワードに加え、認証アプリの6桁のコードを入力する |

OTP登録後はパスワードだけでログインできません。利用できる組み合わせは[認証方法と制限の一覧](features/administration.md#ログイン方法)を確認してください。

| 期限・状態 | 画面で行うこと |
| --- | --- |
| ログイン中で、重要操作の本人確認が必要 | 案内された再認証画面で本人確認する。10分間有効 |
| 再認証から10分が経過 | 重要操作は拒否される。再認証後に元の画面へ戻り、内容を確認して実行する |
| ログインの期限切れ・ログアウト・サーバー再起動 | ログイン画面から入り直す |

再認証で拒否された操作は自動で再実行しません。画面を開いたまま10分が経過した場合も、実行時に有効期限を検査します。ログイン自体の無操作期限・最長期限は[セッションの仕様](features/administration.md#セッション)を参照してください。

## 設定を変更する流れ

1. 掲示板全体の設定か、特定の板の設定かを確認します。
2. 現在の状態・説明・入力範囲を読み、必要な項目を変更します。
3. 再認証が必要なら、画面が案内するパスキーまたはパスワード＋OTPなどで本人確認します。
4. 保存し、保存後の状態を確認します。

一覧の検索・候補の選択・ページ送りだけでは、設定は保存されません。保存ボタンで確定してください。起動JSONを編集する項目は再起動が必要です。管理画面で保存した運用設定は、起動JSONの初期値より優先されます。

## 閲覧制限と管理用アクセスの違い

| 設定 | 対象 | 主な用途 |
| --- | --- | --- |
| 閲覧制限 | 掲示板全体の公開閲覧・投稿 | 許可する接続元や、拒否する国・回線・クローラーを設定 |
| 板の閲覧制限 | 対象板の公開閲覧・投稿 | 全体の条件に加えて、その板を制限 |
| 管理画面のアクセス | ログイン前を含む管理画面・API・CSS/JS | 管理ページへ接続できる回線やIPを制限 |

管理用アクセスは掲示板の閲覧条件から独立しています。管理画面は設定のON/OFFとは別に検索抑止と既知クローラーの拒否を行います。掲示板側の「拒否するクローラー」を、管理画面への巡回を許可する設定と取り違えないでください。

クローラーは標準の候補を選択するほか、拒否するUA文字列を追加できます。UAの自己申告による判定なので、偽装した相手まで確実に識別する仕組みではありません。[判定の条件](features/reading.md#標準クローラーの判定)を参照してください。

管理用の許可IPを指定するときは、画面に表示される現在の接続元を確認します。回線変更後などに入れなくなった場合は、[管理用アクセス制限の解除](operations.md#管理画面のアクセス制限を解除する)を使います。

## 回線分類を確認する

まず画面上部で、自動更新の状態・直近の結果を確認します。取得に失敗しても、前回成功した分類表と手動上書きは維持します。

カテゴリーと取得元の一覧は、名前などで検索できます。件数・ページを切り替えて対象を探し、必要な項目を開いて編集します。この一覧の検索は画面内の候補を絞る操作で、自動更新の取得元や保存値を変更しません。

誤判定は、対象IP・CIDRと、変更したい分類を確認して手動上書きします。事業者名やASNだけで、利用者の契約サービスを断定できない場合があります。対象と判定順序は[回線分類の仕様](networks.md)を参照してください。

## レスとスレッドを管理する

「板設定」で対象板の「レス削除・投稿者規制」を開き、スレッドを選びます。ログイン中の管理者権限で操作できます。

- レス削除：対象レスの「このレスを削除」を開き、番号と削除内容を確認して実行します。画面から元の公開表示へ戻すことはできません。複数のレスは「レスをまとめて削除」から指定します。非公開原本は書き換えません。[あぼーんと原本の違い](features/records.md#レス削除あぼーんと原本)を参照してください。
- 投稿者規制・解除：必要な再認証を済ませ、対象レスの「この投稿者を規制・解除」を選びます。期間・理由を選ぶと、この板のスレッド作成と返信を制限します。同じ内部IDに適用中の単独の規制は、その画面から解除できます。IP規制や追加条件付き規制は通常の一覧で確認します。
- スレッド停止：「スレッドを停止」から確認画面へ進み、対象を確認して適用します。本文を残したまま新しい返信を停止します。

レスの上下から50件単位でページを切り替えられます。非公開記録を番号で調べる場合は「レス番号を指定して記録を確認」を開きます。記録の内部ID・操作IDは詳細を開いて確認します。

投稿者規制は同じ匿名Cookieの内部IDを対象にし、同じ回線のほかの利用者には広げません。Cookieを変更した投稿者までは追跡できません。内部IDが未記録の場合は、レスの記録から利用できる規制項目を確認します。記録からの規制には板管理者以上の権限、記録の閲覧権限、10分以内の再認証が必要です。

## 削除依頼に対応する

管理メニューの「削除依頼」で、非公開の依頼と連絡先を確認し、状態・担当・回答を管理します。受付だけでレスは削除されないため、削除する場合は対象レスを確認して[レス管理](#レスとスレッドを管理する)から実行します。

利用者は受付時の依頼IDと照会秘密で回答を確認します。公開側の操作手順は[削除依頼・問い合わせ](user-guide.md#削除依頼問い合わせ)を参照してください。

送信間隔は、サイト管理者が「運用設定」→「削除依頼の送信間隔」で1〜1440分から変更できます。初期値は10分です。同じブラウザーは指定期間に1件、同じ接続元IP全体は3件までで、照会は別枠です。保存後すぐに反映し、再起動後も維持します。[受付履歴・共有回線・制限時の扱い](features/abuse.md#削除依頼の操作と送信間隔)を確認してください。

## 提出用ログを取得する

案件一覧には案件番号・状態・板名とキー・スレッド番号・対象件数・保全期限を表示します。案件を開くと対象範囲・保存状況・ZIP取得・保全期限の変更・保全終了を確認できます。新規登録は「新しい案件を作成」を開きます。

1. 管理画面の「提出用ログ」を開き、必要なら再認証します。「記録の閲覧・保全・出力」権限と対象板の担当範囲が必要です。
2. 板・スレッド・対象期間・理由を入力して案件を作成します。
3. 対象範囲と保全期限を確認し、「ZIPを作成してダウンロード」を押します。投稿原本と保存済みの関連HTTPログを保全し、提出可能な全項目を含むZIPを取得します。
4. `records.csv` を開き、板キー `board_key`・スレッド番号 `thread_key`・レス番号 `post_number` と本文 `public_body` を確認します。列の意味や欠測の読み方は同梱の `readme.txt` にあります。
5. 提出先では同梱の公開鍵を別途信頼済みの鍵と照合して署名を確認します。

案件一覧は作成日時の新しい順です。キーワードで案件番号・理由・依頼機関・依頼参照・板名・板キー・スレッド番号を検索し、状態でも絞り込めます。空白区切りの語はすべて含む条件です。並び順は作成日時の新しい順・古い順・保全期限が近い順から選べます。検索条件は次ページにも引き継ぎます。

ZIPは記録種別ごとの全項目を含みます。取得済みZIPは再取得できないため、必要なら案件から新しいZIPを作成します。途中失敗した場合だけ表示される再開操作で、同じ対象の処理を続けます。

「未受理・閲覧ログ」は別の入口です。未受理ログか受付前拒否・閲覧ログのZIPを選ぶと、保全から取得まで実行します。保全前の案件は両方の入口に表示し、取得した種別が決まった後は対応する入口だけに表示します。閲覧ログではスレッド番号を指定できません。

終了案内などの自動投稿はCSVに含めません。保存されていない値は補わず、応答終了時刻も同じ要求のHTTP記録がある場合だけ出力します。[CSVの列・日時・欠測と署名の仕様](features/records.md#提出用ファイル)を参照してください。形式だけを確認する場合は、画面の「架空サンプルをダウンロード（ZIP）」を使えます。

## 管理操作の記録を調べる

管理メニューの「操作の記録」を開きます。画面の見出しは「管理操作の記録」です。

1. 調べたい期間を指定します。期間ボタンやカレンダーでは日本時間で指定し、開始を含み、終了を含みません。JavaScriptが使えない場合はタイムゾーン付きのISO形式で入力します。
2. 操作者を候補から選びます。名前を表示できない操作者はIDで識別します。
3. 操作の候補を開き、例えば「パスキー」「回線」「規制」で検索して選びます。
4. 必要なら板を選び、1ページの件数を指定して「絞り込む」を押します。
5. 操作の説明と対象を確認し、IDや操作コードが必要なら「記録の詳細」を開きます。

| 表示 | 読み方 |
| --- | --- |
| 一覧の日時 | 日本時間。カレンダーによる期間指定も日本時間 |
| 操作名・説明・対象 | 何の操作か、どの板・項目を扱ったか |
| 操作者名 | 現在の登録名。本人または再認証済みサイト管理者の権限内で表示 |
| 詳細の項目一覧 | 操作が扱う設定項目。項目ごとの変更前後の値は保存しない |
| 保存形式を更新 | 新機能に対応する保存形式への更新。運用設定そのものの変更とは区別する |
| 期限切れデータの整理基準時刻を記録 | 一時データを整理する前の内部処理。操作記録の保存期間の変更ではない |
| スレッド本文の削除に伴う一覧順序の基準を記録 | 本文の保存領域を解放する処理に伴う記録。これだけでは本文削除完了を示さない |
| 原本ログの自動整理の進捗を記録 | 整理が進んだ段階の記録。整理全体の完了を示すとは限らない |
| CAPコマンドの「開始」 | 完了は未確認。「完了」の記録とは別 |
| 詳細未記録の管理操作 | 要約からは種別を判別できず、元の操作ログからも復元できなかった記録 |

操作候補の検索は画面内で行い、選択後の「絞り込む」で記録を取得します。JavaScriptが使えない場合も、候補の一覧から選んで送信できます。

「次のページ」は取得時点の一覧を使い、10分間保持します。最新の変更を見るときは「直近24時間を再取得」または「条件をリセット」を使います。旧分類の「その他」でも、対応する操作コードが元ログに残っていれば、具体的な操作名で表示・検索します。元ログが回収済みで要約しか残らない記録は、復元できない場合があります。

この一覧は管理操作の要約です。パスキー・OTPの状態保存に伴う記録が含まれる場合もありますが、すべてのログイン試行や未保存の失敗を網羅しません。認証の成否は[認証監視](security-operations.md#認証監視)、投稿の非公開原本は[記録・削除・保持期限](features/records.md)を参照してください。

## 画面を開けない・保存できないとき

| 状態 | 確認・次の操作 |
| --- | --- |
| ログインの有効期限が切れた | 説明付きのログイン画面から入り直す。再起動でも全セッションが失効する |
| 再認証を求められた | 現在のログイン設定で本人確認する。[利用できる方法](features/administration.md#ログイン方法)を確認 |
| 権限が足りない | ロール・担当板・追加権限を確認する。再認証だけでは解決しない |
| 接続元の制限でログイン画面も開けない | サーバー側で[管理用アクセス制限を解除](operations.md#管理画面のアクセス制限を解除する) |
| 古い設定との競合を通知された | 最新の内容を確認してから入力し直す |
| 保存結果が分からない | 内容と要求IDを変えず、同じ要求で結果を確認する |
| 操作記録のページ送りが期限切れになった | 条件を指定し直して取得する |
| HTMLの待機が長い | [応答待ちの確認](operations.md#管理画面の応答待ちを調べる)でアプリ処理と通信を切り分ける |
