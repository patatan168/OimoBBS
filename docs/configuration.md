# 起動設定

[config.example.json](../config.example.json)をコピーして使用します。起動JSONは64KiB以内の厳密なUTF-8 JSONです。全項目が必須で、重複・未知項目・型違いを拒否します。未使用の任意機能も省略せず `null` を指定します。

| 項目 | 設定例・用途 |
| --- | --- |
| `schema_version` | `1`。起動設定の形式 |
| `data_dir` | `./var/site`。永続保存先 |
| `public.listen` | `127.0.0.1:9080`。公開待受 |
| `public.base_url` | `http://127.0.0.1:9080`。利用者から見えるOrigin |
| `public.tls_cert_file` | ローカルHTTPでは空文字。HTTPSではPEM証明書チェーン |
| `public.tls_key_file` | ローカルHTTPでは空文字。HTTPSではPEM秘密鍵 |
| `admin.listen` | 通常の `public_path` は空文字。別待受方式だけアドレスを指定 |
| `admin.transport` | 通常は `public_path`。旧別待受は `loopback_tunnel` / `direct_https` |
| `admin.origin` | 公開と同じOriginに管理パスを付けたURL |
| `trusted_proxies` | 通常は `[]`。転送ヘッダだけを信頼する設定にしない |
| `cache_bytes` | `268435456`。起動時の資源予算。必須、1〜1TiB |
| `egress_budget_bits_per_second` | `80000000`。必須、1〜1,000,000,000bit/s |
| `edge` | 通常は `null`。管理下の単一mTLS終端用 |
| `maintenance` | 自動整理設定。未指定の機能は `null` |
| `auto_reports` | 自動通報の受付板・起点。使わなければ `null` |

相対パスはカレントディレクトリではなく、設定ファイルの場所を基準に解決します。`data_dir` の親は初期化前に作り、保存先自体は `init` に作らせます。所有者・権限・通常ファイルかどうかも検査します。

`base_url` はscheme・host・portだけを指定します。`admin.origin` は `public_path` の場合だけ管理パスを付け、他の方式ではscheme・host・portだけにします。query・ユーザー情報は付けません。HTTP公開は明示したloopback試験だけに限定します。HTTPSの証明書名・期限・鍵対応を検査します。

## どこで設定し、いつ反映するか

| 設定の種類 | 設定する場所 | 反映と優先順位 |
| --- | --- | --- |
| 保存先・待受・公開URL・TLS・管理接続方式 | 起動JSON | 再起動で反映 |
| 帯域・キャッシュ・自動整理・通報条件 | 起動JSONの初期値、管理画面の運用設定 | 管理画面の保存値があればそちらを優先 |
| 板の入力・表示・投稿条件、カテゴリー | 管理画面のサイト・板設定 | 保存後の対象操作に適用 |
| 新規スレッドのレス数上限 | 管理画面の板別設定 | 変更後に作るスレッドへ適用 |
| 終了レス | 管理画面の板別設定 | スレッド終了時の設定を適用 |
| 閲覧制限・管理用のアクセス制限 | それぞれの管理画面 | 保存後の要求・送信時に検査。起動JSONへ追加しない |
| 回線分類の取得元・手動上書き | 管理画面の回線分類 | 保存値を維持。自動取得は全取得元の検査成功時だけ更新 |

板やCookieの条件は[確定仕様](specification.md)、操作は[運用手順](operations.md)を参照してください。

## 自動整理

`maintenance` を有効にする例です。

```json
{
  "enabled": true,
  "max_seconds": 5,
  "interval_seconds": 300,
  "max_threads": 5
}
```

これは `maintenance` の値です。設定ファイル全体ではありません。間隔は60〜86400秒、一回の対象は1〜1000スレッド、時間予算は最大300秒です。書込み途中を時間切れで強制中断しません。

## 自動通報

`auto_reports` は次の形です。初回は `auto_reports: null` で初期化し、受付板を先に作ります。その後サーバーを停止して設定を追加し、再起動します。`since` は運用開始時の過去または現在のRFC3339時刻に置き換えます。

```json
{
  "board_key": "report",
  "since": "2026-10-11T00:00:00Z"
}
```

集計期間・停止票数・停止時間は管理画面の「運用設定」で編集します。

板ごとの有効／無効は「板設定」の「通報機能（!report）」で切り替えます。板管理者は担当板、サイト管理者は全板を設定できます。無効にした板への通報は、通常スレッドの `!report`・板の受付スレッド・共通受付板のいずれからも集計しません。通常スレッドの `!report` は公開投稿として受理し、受付スレッドへの新しい通報は拒否します。切り替えは保存後すぐに反映され、再起動後も保持します。切り替えると対象板の集計を開始し直し、通報履歴と成立済みの停止期限は保持します。

既存の板は有効を引き継ぎます。起動設定の `auto_reports` が `null` の場合は、板設定が有効でも通報機能は動きません。板設定の保存はreader84以降を宣言し、新形式を保存した後は旧バイナリで開けません。

## 管理画面の運用設定

起動JSONは初期値です。管理画面で保存した運用設定がある場合は保存値を優先します。JSONを編集して再起動しても、保存済み設定を上書きしません。

| 設定 | 管理画面の範囲 |
| --- | --- |
| 整理間隔 | 1〜1440分 |
| 一回の整理 | 1〜1000スレッド、1〜300秒 |
| 通報集計 | 1〜10080分 |
| 停止票数 | 1〜20票 |
| 自動停止 | 1〜1440分 |
| 共通送信予算 | 1〜1000Mbps、1Mbps単位 |
| 共有キャッシュ | 0〜128MiB、1MiB単位 |
| HTML生成・圧縮の同時処理 | 1〜8件 |

未保存時の共有キャッシュは `min(cache_bytes / 4, 16MiB)` です。送信予算は公開と管理で共有し、本文・推定ヘッダ・通信分の見積もりに適用します。

## 管理下のTLS終端

通常のセットアップはアプリへの直結HTTPSです。終端を別に置く場合は [EdgeConfig](../internal/bootstrap/proxy.go) の厳密な設定型と検査に従い、mTLSで接続先と終端を認証し、元IP・元ポート・宛先・要求ID・時刻の専用ヘッダを揃えます。外部から届いた同名ヘッダは終端が削除して上書きします。

任意の `X-Forwarded-For` は信用しません。この設定は管理下の単一終端用です。

## 管理HTTPSの公開

`admin.transport: public_path` は、掲示板と同じHTTPS Originの管理パスへ管理画面を登録します。`admin.origin` に同じscheme・host・portと `/admin/` を指定します。管理専用ポートは開かず、公開側のHTTP観測には管理要求を記録しません。認証済み `edge` も併用でき、管理要求は公開のHTTP観測から分離したまま、mTLSと接続元の確認を通します。公開入口の `--admin-path` に同じマウント先を指定します。管理経路だけPATCHと最大256 KiBの本文転送を許可し、各管理操作は自身の入力上限も検査します。

設定例と公開手順は[管理HTTPSのセットアップ](setup.md#管理画面を同じポートで公開する)です。新規セットアップは同じ待受を既定にします。HTTPは明示したloopback試験の場合だけ同じ方式を使えます。変更には再起動が必要です。

別の管理HTTPS待受が必要な場合は `direct_https` も利用できます。この場合だけ `admin.listen` を外部待受へ変更し、公開Originと異なるHTTPS `admin.origin` を指定します。公開用TLS証明書・鍵を共用し、両方の名前・期限・鍵対応を検査します。

## 回線分類の標準設定

初回サーバー起動で未設定サイトに国内204 ASN・VPN事業者/共有基盤7 ASN、国コード、日本IP、既知VPNの24時間更新を設定します。`init`・`check`などのオフライン操作では外部取得しません。保存済みの設定・停止状態は変更しません。管理画面「回線分類」で更新状況と誤判定を確認できます。

既存サイトの「国内・VPN業者の標準取得元を追加して更新」は不足分だけを加え、同一ASNの設定・カテゴリー・手動上書き・更新間隔を維持します。自動更新は有効になります。取得元とカテゴリーは最大256件です。枠を超える追加は保存せず、現在設定を維持します。

ASNは最大8件ずつ取得し、国/VPNと合わせた1回の取得期限は25秒です。失敗後は1時間、成功後は設定した更新間隔で再取得します。一部成功した表は反映しません。対象と共有上流の注意は[国内回線カタログ](networks.md)を参照してください。

拡張上限を使った設定、大きな自動表の圧縮保存、管理者未登録サイトの初回自動設定はreader 81以降の保存形式です。制御JSONの1MiB上限は維持し、圧縮表にも展開上限と厳密な行検査を適用します。旧バイナリでは開けません。

## 閲覧設定と管理画面へのアクセス

起動JSONには追加しません。管理画面の「閲覧制限」は掲示板全体、「板設定 → 閲覧権限」は板ごと、「管理画面のアクセス」は管理ページ専用の条件です。いずれも初期値はOFFで、保存値は再起動後も維持します。管理用設定は掲示板の閲覧設定から独立しています。

条件の優先順位は[確定仕様](specification.md#閲覧と投稿の許可)を参照してください。逆引き・サービス分類に必要な初回DNS待機は750ms以内です。

APIの `allow_local_ip` と `allow_loopback_ip` はtrue＝許可、false＝拒否、null＝従来の回線条件です。旧形式では両方を省略できますが、新形式では両方を指定します。

板別画面には現在の掲示板全体の閲覧設定を表示します。全体設定がONのとき、共通で拒否されている回線・特殊アドレス・VPN・逆引き不可・クローラーや、日本限定で固定される入力は編集できません。固定中も板固有の保存値は保持し、共通の条件を解除すると編集を再開できます。IP/CIDR・UA・国コードのリストは共通の内容を確認しながら板側で追加制限できます。

管理APIは `GET/POST /api/v1/reading`、`GET/POST /api/v1/boards/<板UUID>/reading`、`GET/POST /api/v1/admin-access` です。GETは設定・ETag・X-CSRF-Tokenを返します。POSTは全フィールドを持つReadingPolicy JSON、If-Match、Idempotency-Key、経路別X-CSRF-Token、同一Originを必要とします。管理パスを使う場合は各URLの先頭に設定したパスを付けます。閲覧拒否は403、現在の管理接続元を拒否する保存は422、古い版は412です。

現在の実装で閲覧設定を保存・管理用制限を解除するとreader83を宣言します。reader82の旧設定は従来の条件を保って読み込みます。旧バイナリは開けません。制限をOFFにしても保存形式を旧版へ戻しません。解除手順は[運用手順](operations.md#管理画面のアクセス制限を解除する)を参照してください。

固定回線のDNS補完は、逆引きした名前を正引きし、元のIPとの一致を確認した場合だけ適用します。対象は UCOM の `*.ftth.ucom.ne.jp`、OCN の `p数字-ipngn数字.*.ocn.ne.jp`、au one net の `*.ppp-bb.dion.ne.jp`、So-net の `*.ap.so-net.ne.jp`、NURO の `*.ap.nuro.jp` です。携帯・公衆Wi-Fiと混在するISP全体を固定回線に変更せず、共通・板別の明示上書きと国・既知VPNの判定を優先します。
