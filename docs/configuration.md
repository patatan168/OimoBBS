# 設定一覧

設定は起動JSONと、管理画面から保存する運用・板別設定に分かれます。変更する場所と反映時点を確認してから編集してください。

## どこで設定し、いつ反映するか

| 設定の種類 | 設定する場所 | 反映と優先順位 |
| --- | --- | --- |
| 保存先・待受・公開URL・TLS・管理接続方式 | 起動JSON | 再起動で反映 |
| 帯域・自動整理・通報条件 | 起動JSONの初期値、管理画面の運用設定 | 管理画面の保存値があればそちらを優先 |
| 板の入力・表示・投稿条件、カテゴリー | 管理画面のサイト・板設定 | 保存後の対象操作に適用 |
| 新規スレッドのレス数上限 | 管理画面の板別設定 | 変更後に作るスレッドへ適用 |
| 終了レス | 管理画面の板別設定 | スレッド終了時の設定を適用 |
| 閲覧制限・管理用のアクセス制限 | それぞれの管理画面 | 保存後の要求・送信時に検査。起動JSONへ追加しない |
| WAFの有効状態・頻度・同時処理上限 | 管理画面のWAF | 保存後すぐに反映。再起動後も維持 |
| 回線分類の取得元・手動上書き | 管理画面の回線分類 | 保存値を維持。自動取得は全取得元の検査成功時だけ更新 |

設定を変更したのに反映されない場合は、管理画面の保存値が起動JSONより優先されていないか、再起動が必要な項目でないかを確認してください。板・Cookieの条件は[仕様の全体像](specification.md)、操作は[運用手順](operations.md)を参照してください。

## 変更する場所の選び方

1. URL・ポート・証明書・保存先を変える場合は、起動JSONを編集して再起動します。
2. 板の表示・投稿条件や、帯域・通報条件を変える場合は、管理画面で保存します。
3. 期待どおりに変わらない場合は、上の表で反映時点と優先順位を確認します。保存済みの運用設定は、起動JSONの書き換えでは上書きできません。

JSONの例が「`maintenance` の値」などと説明されている場合は、その項目の中身だけを示しています。設定ファイル全体を置き換えず、対象項目を編集してください。

## 起動JSON

[config.example.json](../config.example.json)をコピーして使用します。起動JSONは64KiB以内の厳密なUTF-8 JSONです。必須項目の欠落、重複・未知項目・型違いを拒否します。設定例の任意機能を使わない場合は `null` のままにします。

| 項目 | 設定例・用途 |
| --- | --- |
| `schema_version` | `1`。起動設定の形式 |
| `data_dir` | `./var/site`。永続保存先 |
| `public.listen` | `0.0.0.0:443`。HTTPS公開待受 |
| `public.base_url` | `https://bbs.example.com`。利用者から見えるOrigin |
| `public.tls_cert_file` | HTTPSのPEM証明書チェーン。例 `./tls/fullchain.pem` |
| `public.tls_key_file` | HTTPSのPEM秘密鍵。例 `./tls/privkey.pem` |
| `admin.listen` | 通常の `public_path` は空文字。別待受方式だけアドレスを指定 |
| `admin.transport` | 通常は `public_path`。旧別待受は `loopback_tunnel` / `direct_https` |
| `admin.origin` | 公開と同じOriginに管理パスを付けたURL |
| `trusted_proxies` | 通常は `[]`。転送ヘッダだけを信頼する設定にしない |
| `egress_budget_bits_per_second` | `80000000`。必須、1〜100,000,000,000bit/s（100Gbps） |
| `edge` | 通常は `null`。管理下の単一mTLS終端用 |
| `maintenance` | 自動整理設定。未指定の機能は `null` |
| `auto_reports` | 自動通報の受付板・起点。使わなければ `null` |

### パスと権限

相対パスは設定ファイルの場所を基準に解決します。`data_dir` の親は初期化前に作り、保存先自体は `init` に作らせます。所有者・権限・ファイル種別も検査します。スクリプトの `--tls-cert`・`--tls-key` は呼出時の作業ディレクトリ基準で受け取り、JSONへ絶対パスを保存します。

### 公開URLと証明書

`public.base_url` は `https://bbs.example.com` のように、scheme（http/https）・ホスト・ポートだけを指定します。`admin.origin` は `public_path` の場合だけ管理パスを付け、他の方式ではOriginだけにします。クエリ・ユーザー情報は付けません。

既定はHTTPSのみです。セットアップでHTTPを使う場合は `--allow-http` とloopbackのHTTP URLを明示します。手動検証用の例は [config.local.example.json](../config.local.example.json) です。HTTPを使う場合も外部公開は許可しません。HTTPSでは証明書名・期限・秘密鍵との対応を検査します。

## 自動整理

### packの定期整理

`maintenance` は保存packの圧縮・旧世代整理の間隔と処理量を設定します。有効にする例です。

```json
{
  "enabled": true,
  "max_seconds": 5,
  "interval_seconds": 300,
  "max_threads": 5
}
```

これは `maintenance` の値です。設定ファイル全体ではありません。間隔は60〜86400秒、一回の対象は1〜1000スレッド、時間予算は最大300秒です。書込み途中を時間切れで強制中断しません。

### 期限回収・容量不足時の回収

公開起動の `serve` は、公開本文・満了原本の自動回収と容量不足時の早期回収を有効にします。`maintenance.enabled` をOFFにしても、これらの回収は止まりません。放置期間7日と容量の開始・終了基準は実装の固定値で、起動JSONや運用設定の入力項目ではありません。

対象・順序・容量基準は[記録と回収](features/records.md#容量不足時の自動回収)、稼働中の確認は[容量の確認手順](operations.md#保存容量を確認する)を参照してください。

## 自動通報

`auto_reports` は次の形です。初回は `auto_reports: null` で初期化し、受付板を先に作ります。その後サーバーを停止して設定を追加し、再起動します。`since` は運用開始時の過去または現在のRFC3339時刻に置き換えます。

```json
{
  "board_key": "report",
  "since": "2026-10-11T00:00:00Z"
}
```

集計期間・停止票数・停止時間は管理画面の「運用設定」で編集します。

板ごとの有効／無効は「板設定」の「通報機能（!report）」で切り替えます。板管理者は担当板、サイト管理者は全板を設定できます。無効にした板への通報は、通常スレッドの `!report`・板の受付スレッド・共通受付板のいずれからも集計しません。通常スレッドの `!report` は公開投稿として受理し、受付スレッドへの新しい通報は拒否します。切り替えは保存後すぐに反映され、再起動後も保持します。切り替えると対象板の集計を開始し直し、通報履歴と成立済みの停止期限は保持します。

既存の板は有効を引き継ぎます。起動設定の `auto_reports` が `null` の場合は、板設定が有効でも通報機能は動きません。板設定の保存はreader84以降を宣言します。

## 管理画面の運用設定

起動JSONは初期値です。管理画面で保存した運用設定がある場合は保存値を優先します。JSONを編集して再起動しても、保存済み設定を上書きしません。

| 設定 | 管理画面の範囲 |
| --- | --- |
| 整理間隔 | 1〜1440分 |
| 一回の整理 | 1〜1000スレッド、1〜300秒 |
| 通報集計 | 1〜10080分 |
| 停止票数 | 1〜20票 |
| 自動停止 | 1〜1440分 |
| 削除依頼の送信間隔 | 1〜1440分。初期値10分 |
| 共通送信予算 | 1〜100000Mbps（100Gbps）、1Mbps単位 |
| 公開本文・圧縮結果の保持上限 | 全自動。現在値を表示。手動設定なし |
| HTML生成・圧縮の同時処理 | 全自動。現在値を表示。手動設定なし |

### CPU・メモリへの自動追従

公開本文・圧縮結果の保持上限と、HTML生成・圧縮の同時処理数は全自動です。管理画面では現在値を確認でき、手動値は指定できません。空きメモリが減ると縮小し、回復すると再び増やします。

コンテナの上限が必要なら、例えば `OIMO_CPUS=4 OIMO_MEMORY=3g docker compose ... up` のように指定し、コンテナを再作成します。上限を省略したBBSはホスト資源へ追従します。

計算方法、圧迫時の受付と再開、API・旧保存形式の扱いは[CPU・メモリ・帯域の管理](features/resources.md)にまとめています。

## 管理下のTLS終端

通常のセットアップはアプリへの直結HTTPSです。終端を別に置く場合は [EdgeConfig](../internal/bootstrap/proxy.go) の厳密な設定型と検査に従い、mTLSで接続先と終端を認証し、元IP・元ポート・宛先・要求ID・時刻の専用ヘッダを揃えます。外部から届いた同名ヘッダは終端が削除して上書きします。

任意の `X-Forwarded-For` は信用しません。この設定は管理下の単一終端用です。

## 管理HTTPSの公開

`admin.transport: public_path` は、掲示板と同じHTTPS Originの管理パスへ管理画面を登録します。`admin.origin` に同じscheme・host・portと `/admin/` を指定します。管理専用ポートは開かず、公開側のHTTP観測には管理要求を記録しません。認証済み `edge` も併用でき、管理要求は公開のHTTP観測から分離したまま、mTLSと接続元の確認を通します。公開入口の `--admin-path` に同じマウント先を指定します。管理経路だけPATCHと最大256 KiBの本文転送を許可し、各管理操作は自身の入力上限も検査します。

設定例と公開手順は[管理HTTPSのセットアップ](setup.md#管理画面を同じポートで公開する)です。新規セットアップは同じ待受を既定にします。HTTPは明示したloopback試験の場合だけ同じ方式を使えます。変更には再起動が必要です。

別の管理HTTPS待受が必要な場合は `direct_https` も利用できます。この場合だけ `admin.listen` を外部待受へ変更し、公開Originと異なるHTTPS `admin.origin` を指定します。公開用TLS証明書・鍵を共用し、両方の名前・期限・鍵対応を検査します。

## 回線分類の標準設定

未設定サイトの初回サーバー起動で、[標準カタログ](networks.md)のASN・国コード・日本IP・既知VPNを24時間ごとに更新する設定を作ります。`init`・`check`などのオフライン操作では外部取得しません。保存済みの設定・停止状態は変更しません。管理画面「回線分類」で更新状況と誤判定を確認できます。

既存サイトの「全業者の標準取得元を追加して更新」は不足分だけを加え、同一ASNの設定・カテゴリー・手動上書き・更新間隔を維持します。自動更新は有効になります。取得元とカテゴリーは最大256件です。枠を超える追加は保存せず、現在設定を維持します。

ASNは最大8件ずつ取得し、国/VPNと合わせた1回の取得期限は25秒です。失敗後は1時間、成功後は設定した更新間隔で再取得します。一部成功した表は反映しません。対象と共有上流の注意は[国内回線カタログ](networks.md)を参照してください。

回線分類の圧縮値はZstandardで保存します。この圧縮値または拡張容量を使う保存には最低reader102が必要です。小さい設定・分類表は通常JSONのまま保存します。更新用の制御操作JSONは最大2MiB、その他の通常操作は1MiBです。圧縮表には展開長・件数・CRCと厳密な行検査を適用します。旧gzip保存値を読む互換経路はありません。保存容量は[回線カタログ](networks.md#容量と互換性)、サイト全体の形式は[現在の保存形式](operations.md#現在の保存形式)を参照してください。

## 閲覧設定と管理画面へのアクセス

起動JSONには追加しません。管理画面の「閲覧制限」は掲示板全体、「板設定 → 閲覧権限」は板ごと、「管理画面のアクセス」は管理ページ専用の条件です。いずれも初期値はOFFで、保存値は再起動後も維持します。管理用設定は掲示板の閲覧設定から独立しています。

条件の優先順位は[閲覧と投稿の許可](features/reading.md#閲覧と投稿の許可)を参照してください。逆引き・サービス分類に必要な初回DNS待機は750ms以内です。

APIの `allow_local_ip` と `allow_loopback_ip` はtrue＝許可、false＝拒否、null＝従来の回線条件です。旧形式では両方を省略できますが、新形式では両方を指定します。

板別画面には現在の掲示板全体の閲覧設定を表示します。全体設定がONのとき、共通で拒否されている回線・特殊アドレス・VPN・逆引き不可・クローラーや、日本限定で固定される入力は編集できません。固定中も板固有の保存値は保持し、共通の条件を解除すると編集を再開できます。IP/CIDR・UA・国コードのリストは共通の内容を確認しながら板側で追加制限できます。

管理APIは `GET/POST /api/v1/reading`、`GET/POST /api/v1/boards/<板UUID>/reading`、`GET/POST /api/v1/admin-access` です。GETは設定・ETag・X-CSRF-Tokenを返します。POSTは全フィールドを持つReadingPolicy JSON、If-Match、Idempotency-Key、経路別X-CSRF-Token、同一Originを必要とします。管理パスを使う場合は各URLの先頭に設定したパスを付けます。閲覧拒否は403、現在の管理接続元を拒否する保存は422、古い版は412です。

現在の実装で閲覧設定を保存・管理用制限を解除するとreader83を宣言します。reader82の旧設定は従来の条件を保って読み込みます。解除手順は[運用手順](operations.md#管理画面のアクセス制限を解除する)を参照してください。

DNSによる固定回線の補完対象と判定順序は[回線カタログ](networks.md#固定回線のdns補完)を参照してください。
