# 投稿規制・荒らし対策

投稿頻度、条件規制、類似文・埋め立て検出と、Cookie単位の停止条件を説明します。

[仕様の全体像](../specification.md) · [文書一覧](../README.md)

## 組み合わせる規制

IP・Cookieの投稿枠、WAFの頻度・同時処理制限、Cookieの発行・待機、IP/CIDR・本文・URL・Cookie・CAP・UAなどの条件規制を組み合わせます。条件規制は最大8条件のANDや許可例外を扱います。回線・国・VPNの許可は板別です。

## 投稿枠と超過時の応答

| 対象 | 補充・期間の初期条件 | burst（蓄積できる枠） |
| --- | --- | --- |
| IP別の返信 | 1件/秒 | 3件 |
| IP別のスレ立て | 1件/600秒、かつ61分に6件まで | 1件 |
| IP別の投稿試行 | 10件/秒 | 20件 |

サイト全体200件/秒・ネットワーク全体60件/秒の固定投稿枠は、現行サーバーの公開受付開始後には適用しません。全体の頻度・同時処理は[WAF](../waf.md)で設定し、受付列、メモリ予約、保存容量でも過負荷を抑えます。CPU・メモリを増やしても固定件数で頭打ちにしないための変更です。

初回の公開受付開始時に切り替え時刻と最低reader90を同期保存します。切り替え前の投稿履歴は従来の固定枠でも復旧検査し、それ以降の投稿は新しい条件で復旧します。利用者の投稿間隔・Cookie・条件規制と、その消費履歴は維持します。

投稿試行には確認・失敗・再送も含みます。burstは短時間に使える蓄積枠で、すべての利用者へ常にその件数を保証するものではありません。板別・共通の設定と他の規制も検査します。枠不足は429と `Retry-After`（再試行までの待機）を返します。

## 共通設定と板別設定の関係

「掲示板全体の荒らし対策」で共通条件を初めて保存すると、投稿枠とCookie待機を全板へ適用し、新設板にも適用します。初回保存前は既存の板別設定を維持します。変更・無効化・再有効化で利用量をリセットしません。

## 類似文・埋め立て検出

追加の類似文・埋め立て検出は、無効・検出のみ・拒否を選べます。

| 条件 | 初期値 | 設定範囲 |
| --- | --- | --- |
| 類似文の期間 | 300秒 | 1〜600秒 |
| 比較する直近投稿 | 50件 | 1〜128件 |
| 類似度 | 90% | 50〜100% |
| 既存の類似投稿数 | 3件 | 1〜比較投稿数 |
| 近似比較の最低文字数 | 12文字 | 3〜1000文字 |
| 埋め立ての期間 | 30秒 | 1〜600秒 |
| 一スレッドの許容投稿 | 100件 | 2〜4000件 |
| 同一IPまたはCookieの許容投稿 | 30件 | 2〜4000件 |
| 占有判定の最低投稿 | 15件 | 2〜4000件 |
| 同一主体の占有率 | 80% | 50〜100% |

初期動作は検出のみです。類似文は空白を畳んだ文字3個の組に対するJaccard比で比較し、短文は完全一致を使います。認証済みCAPの追加対策免除を選べますが、既存の規制の免除には使いません。管理用検出一覧は直近100件で、再起動すると消えます。正常な定型文も検出し得るため、条件を管理者が調整します。

検出履歴は全板合計で直近600秒・最大4096件、本文の比較索引は直近128件まで保持します。履歴が満杯の場合は最古の確定履歴を置き換え、容量不足を検出一覧へ記録します。拒否モードでも、容量不足だけを理由に無関係な投稿を拒否しません。再起動時に履歴を切り詰めた場合も同じです。保持できている履歴による類似文・埋め立て判定と、IP・Cookieの投稿枠、WAF、受付・保存容量の制限は引き続き適用します。古い履歴を捨てるため、混雑時には設定した期間全体を使った検出を保証しません。

## 削除依頼の操作と送信間隔

公開スレッドの各レスにある「削除依頼・問い合わせ」から、板名・スレッド番号・レス番号を入力済みのフォームを開けます。対象を確認して理由を入力します。複数のレスは `1,3-5` のように1件へまとめられます。理由と連絡先は非公開です。受付後に表示される依頼IDと照会秘密を保存し、「受付済み依頼の照会」で回答を確認してください。依頼の受付だけでは投稿は削除されません。

サイト管理者は「運用設定」→「削除依頼の送信間隔」で1〜1440分の間隔を指定できます。初期値は10分です。同じブラウザーのCookieからは指定した期間に1件、同じ接続元IP全体では3件まで受け付けます。板・対象レス・依頼の種類を変えても共通の制限です。設定は保存直後から適用され、再起動後も維持します。間隔を変えても受付履歴はリセットしません。

判定には確定済みの依頼を使い、拒否した送信で待機時間を延ばしません。制限時は429と残り秒数の `Retry-After` を返し、フォームの入力を保持します。照会は別枠です。短時間の大量アクセスには既存のWAFと毎分の試行制限も適用します。

同じIPを共有する利用者は回線全体の上限を共有します。Cookieを削除するとブラウザーの識別は変わりますが、IP側の受付履歴は残ります。異なるIPとCookieを用意した依頼を完全に防ぐものではありません。依頼には用途別HMACによるCookie識別値を保存し、生のCookieは保存しません。既存の依頼はそのまま読み込み、新形式の依頼を保存、または運用設定を更新すると最低reader100を宣言します。以後はreader99以前のバイナリで開けません。

## 自動通報の票と停止対象

自動通報を有効にしている場合、同じCookieまたは同じ接続元からの票は重複して数えません。接続元はIPv4の1アドレス、IPv6の/64単位です。IPv4射影IPv6は同じIPv4として扱います。公開通報・私的通報・再起動時の未成立票の復元に同じ条件を適用し、IPv6アドレスの末尾だけを変えて票数を増やせないようにします。

共有回線の利用者は独立した票として数えられない場合があります。この集約は通報票の重複判定だけに使用し、停止対象を共有IP・ネットワークへ広げません。停止するのは通報対象のCookieによる対象板への投稿です。保存済みの成立した停止は維持し、元の接続IPの保存形式も変更しません。異なるネットワークとCookieを用意した不正通報を完全に防ぐものではありません。

## 攻撃固有の規制によるCookie単位の停止

管理者が指定した攻撃固有のspam規制への違反を、Cookieごとに数えます。条件と停止範囲は次のとおりです。

| 項目 | 条件 |
| --- | --- |
| 停止の成立 | 固定60秒以内に、同じCookieの異なる要求で違反5件 |
| 停止の開始 | 5件目の違反記録を保存した時点 |
| 停止時間 | 600秒。停止中の違反で延長しない |
| 停止する投稿 | 対象Cookieによる全板の新規投稿 |
| 数える規制 | 空白除去後12文字以上の本文exact（完全一致）/contains（含む）、またはURL domain（ドメイン）条件 |
| 数えない規制 | 自動通報由来、IPだけ、短文・正規表現だけの規制、通常枠超過 |
| 再送 | 同じ違反要求は一件。受理済みの同一再送は既存結果を返す |
| CAP | 認証済みCAPは、この追加停止を免除 |

停止はCookie単位で、別Cookieの同じIPを巻き込みません。Cookieの作り直しや未知の攻撃文をすべて防ぐ保証はありません。

## 不正フォームを反復するBotの自動停止

「掲示板全体の荒らし対策」のBot設定は、初期状態で「自動で一時停止」です。「検出のみ」「無効」にも変更できます。類似文・埋め立て対策のモードとは独立しています。

| 項目 | 動作 |
| --- | --- |
| 主体 | 署名・世代・有効期限・失効を検証した匿名Cookie。IPやUAは停止の識別に使わない |
| 数える違反 | Webの非表示欄 `oimo_contact` への入力、非空で構文が壊れたCSRF値 |
| 成立条件 | 最初の違反から固定60秒以内に、異なる違反要求を8件 |
| 再送 | 同じ経路・違反種別・本文バイト列は一件。本文は用途別HMACにして記憶 |
| 停止範囲 | 対象Cookieの全板への新規投稿。Web・専ブラで共通 |
| 停止期間 | 8件目から120秒。停止中の要求で延長せず、自動解除 |
| 保持上限 | 最大4096主体、各主体の要求HMACは8件まで。期限外の項目は要求処理時に回収 |
| 容量不足 | 新規主体の記憶だけを省略し、既存の投稿規制・WAFで保護を継続 |

空のCSRF値、期限切れ、署名不一致だけのCSRF、通常の確認画面、投稿間隔超過は加点しません。同意Cookieは規約変更や期限切れでも無効になるため、確認失敗自体も加点しません。正規形式のCSRFを含むBotやCookieを作り直すBotをすべて識別する仕組みではありません。Cookieがない場合や検証できない場合も、他人のCookieや共有IPを停止させないため追加の記憶対象から除外します。

閲覧、同一IPの別Cookie、認証済みCAP、受理済みの同一再送は追加停止の対象外です。再送照合を先に行うため、新規投稿の拒否前にも本文解析・確認検査・板ワーカー処理は必要です。拒否後の投稿保存・投稿枠の予約は行いません。外部の判定サービス、JavaScript、CAPTCHA、新しい必須フォーム項目は追加しません。

管理画面と `GET /api/v1/abuse-guard` の `data.bot` で、現在の記憶数、停止条件成立中のCookie数、異なる違反数、停止条件の成立数、新規投稿の拒否数、容量不足による記憶省略数を確認できます。「検出のみ」でも成立を数えますが、追加拒否は行いません。集計はプロセス起動後の累計で、IP・Cookie原文・本文は含みません。違反履歴・停止状態・集計はメモリ内だけに保持し、再起動で消えます。モード変更で履歴や停止期限をリセットしません。

設定は既存の管理認証・CSRF・版比較・再送照合・監査付き保存に従います。JSON設定の追加項目は `settings.bot_mode`（`reject` / `observe` / `off`）です。旧APIや更新前のHTMLフォームで省略した場合は稼働中の設定を維持します。旧保存値に項目がない場合も自動停止として動作し、旧署名対象は変更しません。新しい項目を保存したサイトはreader97以降が必要です。

## WAFとの関係

ここで説明する投稿規制は、投稿内容や投稿資格を検査します。[WAF](../waf.md)はHTTP要求の追加検査と頻度・同時処理の制限です。両方を有効にした場合は、それぞれの条件を満たす必要があります。WAFをOFFにしても投稿規制は解除されません。
