## 管理画面の公開と認証

管理画面は、通常、掲示板と同じHTTPSのホスト・ポートに設定した管理パスで開きます。管理用の別ポートは開きません。接続先の設定は[セットアップ](../setup.md#管理画面を同じポートで公開する)を参照してください。

### ログイン方法

普段はパスキーを使い、端末を失ったときに備えて認証アプリのOTPも登録できます。OTPを使う場合は、必ずパスワードと組み合わせます。

| 自分の設定 | 利用できるログイン・再認証 |
| --- | --- |
| OTP未登録、ログイン制限は無効 | パスワード、または登録済みのパスキー |
| OTP未登録、ログイン制限は有効 | 登録済みのパスキーのみ |
| OTP登録済み、ログイン制限は有効・無効のどちらでも | パスワード＋OTP、または登録済みのパスキー |

OTP単独ではログインできません。OTP登録後は、ログイン制限のチェックを外してもパスワード単独ではログインできません。

パスキーの場合はログイン名を入力せず、「パスキーでログイン」を押して端末の画面でアカウントを選びます。パスワードの場合はログイン名とパスワードを入力します。パスワード＋OTPの場合は両方を入力し、「パスワードとOTPでログイン」を押します。

### 再認証が必要なとき

認証手段の変更や非公開記録の操作などでは、ログインとは別に、10分以内の再認証を求めます。上の表と同じ方法で本人確認してください。パスキーでログインした直後でも、重要操作には再認証が必要です。

10分を過ぎた重要操作は拒否されます。本人確認をやり直すと元の管理画面へ戻りますが、拒否された操作は自動で再実行しません。画面を開いたまま期限が切れた場合も、実行時に有効性を確認します。ログイン期限切れとの違いは[ログインと再認証の操作手順](../admin-guide.md#ログインと再認証)を参照してください。

ログイン制限の変更には、パスキーまたはパスワード＋OTPによる再認証が必要です。再認証をしても、担当板や権限の範囲は変わりません。

### パスキー

自分の端末やセキュリティキーを最大16件登録できます。指紋・顔認証やPINで本人確認できる、HTTPSまたはlocalhostの対応ブラウザが必要です。

1. 管理メニューの「パスキー」を開きます。
2. 「再認証して登録・削除へ進む」から本人確認します。すでに10分以内に再認証済みなら、そのまま進めます。
3. 端末を区別できる名前を付け、ブラウザの案内に従って登録します。
4. 以後は、ログイン名を入力せず「パスキーでログイン」を選び、端末の案内に従ってアカウントの選択と本人確認を行います。

ログイン・再認証には、認証器に保存され、選択できるパスキーを使います。以前登録した、認証器に保存されないキーが使えない場合は、利用可能なパスワード認証で入り直して再登録してください。

パスキーを削除すると、本人の全端末がログアウトします。端末に残る鍵は端末側の設定で別途削除します。管理画面のホスト名を変更するときは、変更前に旧ホストのパスキーを削除し、変更後に登録し直してください。

### 認証アプリのOTPとログイン制限

OTPは、スマートフォンの認証アプリが30秒ごとに生成する6桁のコードです。登録場所は管理メニューの「パスキー」です。

#### OTPの登録手順

1. 「パスキー」を開き、10分以内の再認証を済ませます。
2. 「認証アプリのOTP」で「認証アプリへ登録する」を押します。
3. アプリでQRコードを読み取ります。同じスマートフォンで操作中なら「対応する認証アプリで開く」も使えます。読み取れない場合は登録用キーを手動入力します。
4. アプリに表示された6桁のコードを入力し、「コードを確認して登録」を押します。
5. 登録が完了すると全端末がログアウトします。アプリに次のコードが表示されてから、パスワード＋OTPでログインし直します。

手動入力の設定は、**時刻ベース（TOTP）・6桁・30秒・HMAC-SHA1**です。登録用キーの表示は登録開始時だけで、登録待ちの期限は2分です。コードの確認に成功するまではOTPが有効になりません。

QRコードはサーバー内で生成し、外部サービスへ登録用キーを送りません。

#### コードが通らないとき

- サーバーとスマートフォンの時刻を自動設定にします。許容する時刻差は前後30秒です。
- 登録確認・ログイン・再認証で一度使ったコードは再利用できません。次のコードを待ってください。受理済みの区間はサーバー再起動後も再利用できません。
- パスワードも必要です。OTPコードだけでは認証できません。

OTPは偽サイトへの入力によって悪用される可能性があります。普段のログインにはパスキーを推奨します。

#### アカウントごとのログイン制限

同じ画面の「パスキーまたはパスワード＋OTPだけを受け付ける」で、自分のパスワード単独認証を禁止できます。他の管理者の設定には影響しません。再認証前は現在の設定（有効・無効）だけを表示し、変更用のチェックボックスと保存ボタンは表示しません。

1. 少なくとも一つのパスキー、またはOTPを登録します。
2. パスキーまたはパスワード＋OTPで再認証します。
3. チェックを入れ、「ログイン制限を保存」を押します。
4. 全端末がログアウトするので、許可した方法でログインし直します。

有効な間は、最後に残ったパスキー・OTPを削除できません。OTPの登録・解除も全端末のログアウトを伴います。

### ログインできない管理者の復旧

| 復旧する対象 | 操作する人・場所 | 復旧方法 |
| --- | --- | --- |
| サイト管理者 | サーバーを操作できる人・停止中のコマンド | `admin reset-password` で新しいパスワードを設定 |
| サイト管理者以外 | 再認証済みのサイト管理者・Web管理画面 | 対象者へ一時パスワードを発行 |

どちらも対象者の全セッション・パスキー・OTP・パスワード単独認証禁止を解除します。サイト管理者へのWebリセット、サイト管理者を降格してからリセットする操作、下位管理者へのコマンドリセットは拒否します。サイト管理者をWebから下位ロールへ変更することもできません。

一時パスワードによる復旧は次の流れです。

1. サイト管理者が対象者の管理画面で「一時パスワードを発行」を押します。
2. 一度だけ表示されるパスワードを、安全な経路で本人へ渡します。有効期限は1時間です。期限切れや表示を失った場合は再発行します。以前の一時パスワードは使えなくなります。
3. 本人が一時パスワードでログインし、15〜128文字の別のパスワードへ変更します。
4. 本人が新しいパスワードでログインし直し、パスキー・OTP・ログイン制限を設定し直します。

本人のパスワード変更が終わるまでは、管理操作・認証手段の登録・再認証・ログイン制限の変更はできません。サイト管理者用のコマンドは[管理パスワードの再設定](../operations.md#管理パスワードの再設定)を参照してください。

### 認証試行とセッションの上限

#### 試行回数

| 対象 | 上限・数え方 |
| --- | --- |
| パスワード単独のログイン・再認証・一時パスワード変更 | 接続元ごとに共通で1分5件 |
| パスキー認証の開始 | 接続元ごとに1分5件。パスワードの枠とは別 |
| パスワード＋OTPのパスワード照合 | 接続元ごとに1分5件。パスワード単独認証の枠とは別 |
| パスワード＋OTPのコード照合 | 正しいパスワードを確認した後に、接続元ごと・アカウントごとに1分5件 |
| ログイントークンの消費 | 接続元ごとに1分32件、全体で1秒16件 |
| パスワード導出処理 | 同時実行2件・待機16件 |

パスワード照合前にはアカウント共通の停止を設けません。これにより、パスワードを知らない相手が別の接続元から失敗を重ねても、そのアカウントの試行枠を使い切れません。一方、分散した接続元からのパスワード推測を、アカウント単位で1分5件へ抑える保証はありません。全体の受付上限と導出処理の上限に加え、WAF有効時はWAFの全体認証制限も適用します。

パスワードを知っている相手のOTP推測には、アカウント共通のコード制限を適用します。その場合もパスキーの試行枠は消費しません。

#### セッション

セッションはログイン状態を表します。端末やブラウザを併用する場合も、次の範囲で保持します。

| 項目 | 上限・動作 |
| --- | --- |
| アカウントごとの件数 | 32件 |
| 33件目のログイン | 本人の最終利用が最も古いセッションを失効させ、新しいログインを受付 |
| サーバー全体の件数 | 10,000件。他の管理者のセッションを追い出すことはない |
| 無操作の期限 | 30分 |
| 作成からの最長期限 | 8時間 |
| 再認証によるCookie更新 | 件数は増えず、作成からの最長期限も延びない |
| サーバー再起動 | 全セッションが失効し、再ログインが必要 |

### 認証の保存・検証仕様

利用者向けの操作手順に対応する、サーバー側の仕様です。

#### パスワードと照合上限

パスワードは15〜128文字です。保存はArgon2id v19、64MiB、3回、並列度4、乱数salt16バイト、導出結果32バイトに固定します。未知のログイン名にもダミーの導出処理を行います。PBKDF2の保存形式と照合は通常バイナリで受け付けません。一時パスワードは192bitの乱数から生成し、同じArgon2idの導出結果だけを保存します。

#### 管理経路とパスキー検証

直結構成と認証済み公開入口に対応し、後者では管理要求にもmTLSと実接続元の確認を適用します。管理パスは公開ページとrobots.txtに掲載せず、管理Cookieはその配下に限定します。全応答の検索抑止、robotsの巡回禁止、既知クローラー403を適用し、管理データは認証後だけに返します。HTTPSの管理CookieはSecure・HttpOnly・SameSite=Strictです。

パスキーのRP IDは設定済みホスト名、Originは設定済みのscheme・host・portに固定します。指紋・顔認証やPINによる本人確認と、認証器への鍵の保存を必須にします。チャレンジは2分有効・一度限り・最大1024件で、別Origin・別アカウント・別ブラウザ・別用途では使えません。

未ログインの認証開始応答は、ログイン名の存在・有効状態・パスキー登録数によらず共通で、鍵ID一覧を返しません。ログイン名の入力は不要で、署名検証時に認証器の本人ID・鍵IDを有効な管理者の登録鍵と照合します。

秘密鍵は認証器が保持します。サーバーは公開鍵、認証器の状態、表示名、登録日時をサイト制御ログへ耐久保存します。確定時に鍵一覧の版と認証世代を再確認し、署名カウンターの巻き戻り警告は拒否します。鍵削除と認証世代の更新を同時に保存し、旧世代のセッションや確定待ちの操作も失効させます。

実装には[go-webauthnの公開API](https://github.com/go-webauthn/webauthn)を使います。APIは `/api/v1/passkey/{login,register,reauth}/{begin,finish}` と `/api/v1/passkey/remove/finish` のPOSTです。登録・再認証・削除にはセッションの `X-CSRF-Token`、ログイン開始にはログイン画面のCSRFと空のJSONオブジェクト `{}` が必要です。旧画面の `login` フィールドも受け付けますが、認証対象の選択には使いません。URLは管理パス配下に配置します。

#### OTPの鍵とコードの保護

OTP照合はRFC6238/RFC4226に沿ってGo標準ライブラリーで実装し、追加の外部依存はありません。共有鍵はAES-256-GCMとランダムnonceで暗号化し、サイトと管理者へ束縛して保存します。登録待ちの鍵もメモリ内では暗号化し、登録待ちは一度限り・最大128件に制限します。

QR画像も標準ライブラリーで生成し、本人の登録待ちとセッションに束縛します。登録完了・期限切れ後には取得できません。コードは定時間比較し、成功した区間を耐久保存できた後だけセッションを発行します。

#### ログイン受付の可用性

ログイン画面の発行ではサーバーに待機記録を作りません。発行時刻と乱数を含むCookieをHMACで検証し、10分の期限・発行前への時計の後退・別プロセスの署名・使用済みトークンの再利用を拒否します。画面表示だけでは共有トークンの待機枠を消費しません。

使用済み記録は10分以内で最大9,600件です。拒否した要求は記録を増やさず、期限内の記録を追い出さずに一度限りの検査を保ちます。

#### 保存形式の互換性

| 保存済みの機能 | 必要な最低reader |
| --- | --- |
| パスキー | 94 |
| パスワード＋OTPの二要素認証 | 96 |

readerは保存形式を読み込める実装の対応版です。サイト全体の[現在の保存形式](../operations.md#現在の保存形式)は運用手順を参照してください。

## 管理者の役割と追加権限

管理者の権限は「ロール」「担当板」「非公開情報の追加権限」で決まります。画面での選び方と操作の比較は[管理者の権限](../admin-permissions.md)を参照してください。

| ロール | 画面の名称 | 操作範囲 |
| --- | --- | --- |
| `moderator` | 投稿・スレッドの管理担当 | 担当板の投稿削除・スレッド公開停止・投稿停止・自動通報の確認。追加権限は個別に付与 |
| `board_admin` | 板管理者 | 投稿管理、板設定・規制・ローカルルール・スレッド設定・アーカイブ・CAP資格の管理。担当板について全追加権限を含む |
| `site_admin` | サイト管理者 | 全板・サイト設定・板追加・管理者への権限付与・運用設定。全追加権限を含む |

ロールは `moderator < board_admin < site_admin` の順です。上位ロールは下位の操作も含みます。site_admin以外は担当板の範囲内に限り、担当板が空なら板を操作できません。site_adminは新設板を含む全板とサイト全体が対象です。

## 非公開情報の追加権限

投稿・スレッドの管理担当は板設定・スレッド一覧・操作記録を閲覧できません。操作対象を指定した削除・公開停止・投稿停止の確認画面は利用できます。追加権限を付与しても、この閲覧制限は解除されません。

管理ナビゲーション（PC・スマホ）、投稿管理画面の関連リンク、マニュアル内の管理画面リンクは現在のロール・追加権限に応じて表示します。権限のないリンクはHTMLに出力しません。再認証が必要な操作は、そのロール・追加権限を持つ管理者にはメニューを表示し、実行時に再認証を検査します。

追加権限は次の2項目です。moderatorには必要な項目だけを付与します。board_admin・site_adminには両方ともロールとして含まれるため、明示許可が空でも利用できます。

| 追加権限 | 画面の名称と許可する操作 |
| --- | --- |
| `private_reports.read` | 削除依頼の閲覧・回答。非公開の依頼本文・連絡先の閲覧と回答 |
| `evidence.manage` | 記録の閲覧・保全・出力。投稿原本・接続記録の照会、案件用コピーの保存・延長・解除、提出用ファイルの出力・ダウンロード |

記録関連の操作は単一の許可で管理します。原本照会・保全・出力には原則として10分以内の再認証が必要です。再認証でも担当外の情報は取得できません。

## 権限の付与と保存

管理者画面とマニュアルは、認可・保存検査と共通の定義から3ロール・2追加権限を説明します。board_admin・site_adminでは追加権限をすべてチェック済み・変更不可にします。site_adminでは全板をチェック済み・変更不可にし、新しく追加した板も自動で担当します。ロールを下げた場合は、自動チェックを個別付与へ転用しません。

JavaScriptなしでも上位ロールの編集画面はチェック済み・変更不可になります。HTMLのsite_admin指定は担当板を空集合として保存し、APIの空でない担当板指定は拒否します。担当板の空集合はsite_adminに限り全板を意味します。実効追加権限はサーバーがロールから決定し、disabled入力が送信されなくても失われません。

上記の3ロール・2追加権限だけを受け付けます。未定義の名前はHTML/API/CLI・保存済みアカウント・変更receiptで拒否します。

更新すると対象管理者の認証世代が進み、既存セッションが失効します。最後の有効なsite_adminの無効化・降格は拒否します。公開配信と非公開記録の送信時には、現在のセッション・世代・ロール・担当板・実効追加権限を再検査します。

## CAPの資格

CAPは板への投稿・スレ立て資格です。管理者ログインとは別です。担当板、有効期限、停止状態、資格の世代を検査します。CAP名はトリップや認証秘密と分けて表示します。

## CAPの非公開管理コマンド

対象板のpost権限があるCAPは、返信フォームから次の非公開操作を実行できます。

| 入力例 | 操作 |
| --- | --- |
| `>>1 !ban 30m` | 対象レスのCookie主体を板内で30分拒否 |
| `>>1 !ban 2h`、`>>1 !ban 7d` | 2時間、7日拒否 |
| `>>1 !ban` | 永久拒否 |
| `>>1 !unban` | 対象主体の板内・手動Cookie完全一致拒否を解除 |
| `>>1 !delete` | 透明削除。レス番号を維持 |
| `>>1 !stop` | 現在スレッドの通常返信を停止 |

入力と対象には次の条件があります。

- 同じスレッドに存在するレス一件を指定します。複数対象は拒否します。
- 時間の単位は小文字の `m`（分）・`h`（時間）・`d`（日）の一つで、最大36,500日です。`1h30m` のような合成時間や、余分な理由の追記は拒否します。
- BANは保持中の署名原本から匿名主体を解決します。CAP・システム・主体欠測のレスは対象にしません。
- `!unban` は板内の手動Cookie完全一致拒否だけを解除します。IP規制などを一括解除する操作ではありません。

管理コマンドの本文は公開レスを作りません。不正なコマンドも通常投稿へ戻しません。公開中で期限内なら、通常返信の停止や上限到達後も管理操作を受け付けます。非公開・期限切れのスレッドは対象外です。

## 日時・期限の入力

管理操作の記録と公開タイトル検索は、日本時間のカレンダーで期間を指定できます。「今日」「昨日」「直近24時間」「直近7日」「直近30日」でまとめて選び、開始・終了を調整してから検索します。「今日」「昨日」は日本時間の暦日、直近の日数は現在からの経過時間です。終了日時は含みません。日付指定をクリアすると、各画面の既定条件へ戻ります。

提出用ログの対象期間にも同じ選択肢があります。CAPの期限は「7日後」「30日後」や「期限なし」、保全期限は日数の候補で入力できます。保全の延長は現在の保全終了から日数を加え、現在から180日を超える候補を選べないようにします。候補を押しただけでは検索・保存・保全は実行しません。

入力補助はサーバー時刻と日本時間を使います。端末のタイムゾーンが異なっても期間は変わりません。未編集の日時は元の精度を保持し、カレンダーで変更すると秒単位で指定します。APIへは記録の検索境界と精度を保持した日時を送ります。JavaScriptを無効にした場合も、元の日時入力欄とフォームを使用できます。
