# 板・スレッドの設定

入力上限、カテゴリー、スレッドの終了条件と、設定が反映される時点を説明します。

[仕様の全体像](../specification.md) · [文書一覧](../README.md)

## 管理する項目

板の入力上限、名無し表示、ID・識別表示、スレ立てと返信の許可、スレ立てのCAP限定、ローカルルール、転載禁止、専ブラ閲覧専用を管理します。投稿設定を変更した後は新しい投稿に適用し、古い確認内容のまま送信された場合は再確認を求めます。

## 板別設定の移動

板別の設定画面には、対象の板名・キーと「設定中」の項目を共通表示します。投稿設定、板名・キー、閲覧権限、レス数上限・終了レス、投稿規制、ローカルルール、レス管理、閉鎖状態へ、同じ板を選び直さず直接移動できます。選択中の項目は色と下線で区別します。狭い画面ではボタンを2列に折り返し、横スクロールを使いません。縦に長い設定の編集中もナビを表示し、高さが小さい画面では本文の領域を確保するため固定を解除します。

## 板を追加する

管理画面の「板の管理」から「新しい板を追加」を開きます。表示する板名（例：雑談）、URLに使う板キー（例：`chat`）、通常板かCAP専用板かを指定します。サイト管理者による10分以内の再認証が必要です。追加後はその板の設定画面へ移動します。

## 板名・キーを変更する

対象板の設定画面から「板名・キーを変更」を開きます。サイト管理者が再認証して保存すると、公開一覧・板の見出し・専ブラ用の板設定へ反映します。板ID・投稿・スレッド・カテゴリー・管理権限は維持します。

キー変更後も旧URLと旧キーを使った投稿フォームは同じ板へ接続します。新しく表示するリンクと投稿フォームには現在のキーを使います。旧キーは他の板では再利用できません。旧キーを最大64件まで保持し、その板自身の旧キーへ戻すこともできます。先頭は英小文字、以降は英小文字・数字・下線で32文字以内で、`test`・`web`・`admin`は予約済みです。

板名・キー変更はサイトの登録情報へ一括保存し、過去の作成記録や投稿本文を更新しません。この機能を保存したサイトはreader 104以降が必要です。

## 板を閉鎖する

「板の管理」から対象板の「板設定」→「板を閉鎖」を開きます。サイト管理者が10分以内に再認証し、確認用の板キーを入力して確定します。閉鎖の取り消しはできません。

閉鎖直後に、板一覧・専ブラ用メニュー・検索から外れます。Web・専ブラによる取得は旧キーのURLも含めて410で拒否し、スレッド作成・返信・CAP管理コマンドも受け付けません。すでに取得中の本文も追加送信を止めます。管理一覧には「閉鎖済み」と表示し、閉鎖日時と通常ログの最終削除期限を確認できます。

閉鎖済みの板は設定画面の入力・保存と関連設定の入口をグレーアウトし、保存済みの値だけを確認できます。板名・キー、閲覧権限、ローカルルール、レス数上限・終了レス、投稿規制の古い編集URLは設定確認画面へ戻します。閉鎖前に開いたフォームや管理APIからの設定変更も409で拒否します。保存済みログのレス削除・投稿者規制は引き続き利用できます。

公開用本文・DATと非公開の投稿原本は、既存の保持期限で順次回収します。閉鎖直後には消去せず、各データの既存期限と、閉鎖から日本時間の6暦月後のうち早い方を削除期限にします。月末の日付丸めがある場合も、この最終期限を適用します。本文・原本の定期回収は閉鎖後も継続し、全体の原本自動整理を無効にしても閉鎖板の整理は継続します。満了後の実消去は有界な定期バッチで進めるため、期限到達と全件の物理回収完了には時間差があります。

容量不足時は、閉鎖板の本文・原本を通常板より優先して回収します。閉鎖板には最終投稿から7日間の待機や固定スレッドの除外を適用せず、公開停止・本文回収済みのスレッドに残る原本も対象です。案件保全中の記録は引き続き保護します。独立したバックアップ・案件保全コピーは、それぞれの保持・回収条件に従います。[記録と削除](records.md#容量不足時の自動回収)も参照してください。

本文・接続情報を含まない板ID・キー予約・閉鎖記録・削除証跡は、復旧時の再公開とキーの再利用を防ぐため残します。閉鎖状態を保存したサイトにはreader105以降が必要です。

## 新規板の入力初期値

| 項目 | 初期値 |
| --- | --- |
| 名前の上限 | 96byte |
| メールの上限 | 64byte |
| 題名の上限 | 128byte |
| 本文の上限 | 4096byte |
| 本文の行数上限 | 60行 |
| 名前省略時の表示 | 名無しさん |
| 日ID | 必須 |
| ワッチョイ | 表示なし |
| スレ立て・返信 | 一般投稿を許可。Cookieや規制などの条件は別途検査 |

上限は正規化した入力を `sjis-compat-v1` で変換したバイト数で検査します。変換できない文字は数値文字参照にするため、見た目の文字数だけでは収まるかを判断できません。本文の行数は改行数＋1で数えます。最終DATの出力も別に検査します。板を編集した場合はその保存値を使います。

## 板とカテゴリーの件数

板は最大128、カテゴリーは最大256です。カテゴリー名・説明・所属・順序を管理画面で編集し、板メニューへ反映します。検索・対象展開を使って編集できます。

## スレッドのレス数と終了レス

新規スレッドのレス数上限は既定1000です。板で変更しても既存スレッドの上限は維持します。設定範囲は1〜10000件で、最初の投稿も通常レス数に含みます。

上限到達時の終了レス2件は、挿入の有無・名前・メール・本文を管理できます。初期状態は1件目のみ有効で、名前は `OimoBBS`、本文は「このスレッドは終了しました。」です。終了レスは終了時点の設定を使います。停止・アーカイブ・非公開・削除は別の管理操作です。

## スレッドを停止・一覧から除外する

管理画面の対象スレッドの状態変更で「投稿停止」または「アーカイブ」を選びます。投稿停止は終了レスを保存して返信を止め、アーカイブは返信を止めてスレッド一覧から外します。アーカイブ後も、DATは通常の保持期限まで読めます。ただし、容量不足時の回収条件を満たすと早期回収される場合があります。

公開閲覧も止める場合は「スレッド全体の公開停止」を使います。これらの管理操作と、DAT・原本を物理回収する処理の違いは[記録と削除](records.md#公開停止と保存データの回収)を参照してください。

## CAPに限定する設定

CAP専用スレッドでは、返信時にも対象板の有効なCAP資格を要求します。本文・容量・規制・Cookie・確認の検査は維持します。CAP専用のスレ立て設定と、返信まで限定する設定は別です。

## 設定の適用時点

| 変更 | 反映する対象・時点 |
| --- | --- |
| 入力・投稿条件 | 変更後の投稿。古い確認内容なら再確認 |
| 板の新規スレッド上限 | 変更後に作るスレッド。既存スレッドの上限は維持 |
| 終了レスの内容 | スレッドが終了する時点 |
| 閲覧制限 | 新しい要求に加え、帯域待機後・送信片でも再検査 |
| 自動整理条件 | 次の整理バッチ |
| 待受・公開URL・証明書・保存先 | 起動設定を変更して再起動 |
