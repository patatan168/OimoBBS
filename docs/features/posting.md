# 投稿・Cookie・識別表示

投稿が成立する条件、通信切断時の再送、匿名Cookieと公開表示を説明します。

[仕様の全体像](../specification.md) · [文書一覧](../README.md)

## 投稿の流れと再送

### 通常の投稿が成立するまで

1. 利用者が板・スレッドと投稿内容を指定します。
2. サーバーが接続元の閲覧許可、投稿先の状態、入力、必要なCAP資格などを検査します。
3. 有効な匿名Cookieがなければ確認フローで発行します。クライアントがCookieを保持し、次の要求で返す必要があります。
4. 専ブラ・Webともに、Cookie使用と利用規約への同意を一度確認します。同じサイト・規約版なら、本文や投稿先の変更でも再確認しません。Webは同一OriginとCSRFも検査します。
5. Cookie待機、投稿枠、条件規制などを検査します。Webでは確認後に設定が変わった場合は再確認を求めます。専ブラでも保存時点の投稿先・表示命令・CAP資格・規制を検査します。
6. 本文と非公開記録を結び付け、耐久保存の成立を確認します。
7. 確定した投稿を公開し、成功結果を返します。

確認・Cookie発行だけでは投稿は成立しません。CAP投稿も同じ検査を通します。

### 通信切断と重複防止

明示的な要求IDを使う場合、IDは投稿先・主体・内容に結び付けます。同じIDで内容を変更した要求は拒否します。受理済みの同一要求は、追加のレスを作らず既存の結果を返します。

保存途中のエラーや応答切断で結果が不明な場合は、内容と要求IDを変えずに再送します。再起動時には保存記録を照合します。

閲覧拒否へ設定が変わった接続元には、受理済みの再送も拒否します。元の投稿はその設定変更だけでは削除しません。

## 匿名Cookie

### 必須になる投稿

Web・専ブラ・CAP・私的通報を含むすべての新規投稿で、有効な匿名Cookieを必須とします。Cookieなしでは確認フローで発行し、返送される前に投稿を保存しません。必須を解除する設定はありません。

### 有効期間・更新・失効

有効期間は30日で、残り7日以下では同じ内部IDのまま更新します。失効・期限・署名・世代を検査します。Cookie発行後の待機は0〜3600秒で設定でき、発行回数の制限、個別・全体失効を提供します。Cookie削除でIP側の利用枠や発行履歴はリセットしません。

管理画面の「匿名Cookie」では状態の確認と全Cookieの失効を行います。全体失効は取り消せず、全員が次の投稿時に再発行フローを通ります。専ブラでも初回・失効後のCookie取得と返送は必要です。規約への同意は専ブラ・Webで共通の同意Cookieに保存し、本文が変わっても再確認しません。発行回数制限や待機時間は引き続き適用します。個別の投稿者への対応は、板の管理人用スレッド一覧から「レス閲覧・規制」を開き、対象レスの記録から内部IDを選んで投稿規制を設定します。HMACの手入力は不要です。

### 秘密と内部IDの扱い

Cookie原文や再利用可能な署名値を公開・記録へ出しません。内部の関連付けには用途別HMACを使います。

## 投稿者の識別表示

### 公開表示と本人確認の違い

日ID、トリップ、CAP表示、回線・国・VPN表示は板設定と投稿資格に従います。公開ID・ワッチョイは本人確認や規制対象の主キーに使いません。

### ワッチョイの生成規則

ワッチョイは独自の `AABB-CCDD` です。各区画は用途を分離したHMAC-SHA256の結果をpaddingなしURL-safe Base64へ変換した先頭2文字です。

| 区画 | 入力 | 変化する条件 |
| --- | --- | --- |
| AA | 板UUID、週、IPv4 /24またはIPv6 /64 | 板、週、ネットワーク |
| BB | 板UUID、運営が指定するプロバイダキー | 板、プロバイダ |
| CC | 板UUID、検証済みCookie内部ID | 板、Cookie ID |
| DD | 板UUID、週、User-Agent分類 | 板、週、UA分類 |

週は日本時間の木曜0時からです。UA分類は括弧内コメントを除き、最大8個のproduct/majorを小文字化して使います。minorやOS・機種のコメントは入力に含めません。

### プロバイダキーと回線分類

プロバイダキーは表示名と独立した最大64byteの小文字英数字・`_.:-`です。同じプロバイダの複数範囲には同じキーを使います。固定回線の通常表示は `ﾜｯﾁｮｲ` です。逆引き不能は `ｱﾝﾀﾀﾞﾚ / h`、PTR名の不正・正引き不一致は登録国コード（不明は `ZZ`）と末尾 `H` を表示します。一時的なDNS障害は区別し、未分類だけでは `h/H` にしません。判定条件と優先順位は[回線分類](../networks.md#逆引きの特殊表示)を参照してください。

固定・携帯の両用途が確認済みの回線は「固定・携帯混在」（`mixed`）として扱い、投稿・閲覧の許可や条件規制で独立して選択できます。混在分類を保存した状態はreader85以降が必要です。分類表・ASN取得元・CIDR上書きを管理でき、未確認のIPから事業者を推測しません。

回線分類は未設定サイトの初回起動時に標準取得元を登録・取得し、以後は設定した周期で更新します。取得失敗時は前回成功表と手動上書きを維持します。対象ASN、取得上限、判定の優先順位は[回線カタログ](../networks.md)を参照してください。共有上流・IPoEでは契約サービス名まで保証できません。

## Cookie使用と利用規約

管理画面の「利用規約・Cookie」（`/terms`）でCookie説明と規約本文を平文で編集します。既定文は日本法の適用、誹謗中傷・脅迫・権利侵害・個人情報の無断掲載・運営妨害の禁止、削除依頼と違反時の対応を含みます。記録・保存期限は現在の案内を基にしています。著作権の帰属と掲示板運営に必要な利用許諾の案内は、無断転載禁止板だけに表示します。それ以外の板は、投稿者が権利を持つ投稿内容の転載・再配信を許可する既定文です。公開画面のフッターから `/web/terms` を開くと、現在の文章をいつでも確認できます。

文章を変更して保存すると、規約版を増やし、変更日時を自動設定します。変更日はOSのタイムゾーンによらずJSTで表示します。同じ文章の保存と同じ要求の再送では、版・変更日は変わりません。旧規約に同意した利用者も、次回の書き込みで新しい規約に同意する必要があります。初期の既定文をまだ編集していない場合、変更日は「初期設定」と表示します。

同意前は投稿・スレッド予約を確定せず、専ブラには従来互換の `2ch_X:cookie` 確認を返します。同意Cookieの有効期間は1年で、Cookieを削除した場合・期限切れ・規約改訂時は再確認します。旧来の投稿内容確認Cookieは同意として受け付けません。管理者の編集にはサイト管理者権限・同一Origin・CSRF・版比較・再送照合を適用し、監査記録を残します。規約の編集は投稿のたびの永続書き込みや外部通信を増やしません。

初期規約の人権侵害に関する項目は、[法務省の案内](https://www.moj.go.jp/JINKEN/jinken88.html)と[警察庁の誹謗中傷への対応案内](https://www.npa.go.jp/bureau/cyber/countermeasures/defamation.html)を参考にしています。同意署名は規約本文の指紋にも結び付け、配備時の既定文の変更でも旧文への同意を流用できません。

Webで返信が確定すると、同じスレッドの最新50レス（`/test/read.cgi/{board}/{key}/l50`）へ303で戻します。受理済み返信の再送も同じ表示先へ戻します。スレッド作成時は作成した投稿への移動を維持します。

専ブラ向けのCookie・規約の確認画面でも、文章内の改行と空行を保持して表示します。
