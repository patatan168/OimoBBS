# OimoBBS確定仕様

現行機能の仕様です。操作は[セットアップ](setup.md)・[運用手順](operations.md)、保存・配信の詳細は[内部設計](architecture.md)を参照してください。

## 用語

| 用語 | 意味 |
| --- | --- |
| 板 | テーマごとにスレッドをまとめる単位。URL用の板キーと内部の板UUIDを持ちます |
| スレッド | 題名と連続したレス番号を持つ投稿のまとまり |
| レス | スレッド内の一件の投稿。最初の投稿もレス数に含みます |
| DAT | 専用ブラウザへ渡す本文。名前・メール・日時と識別表示・本文・題名を行ごとに並べます |
| 匿名Cookie | 投稿資格と同一主体の関連付けに使う、サーバーが発行した署名付きCookie |
| 確認Cookie | 投稿内容・公開条件の確認に使うCookie。匿名Cookieとは目的が異なります |
| CAP | 指定された板で特別な表示・投稿権限を持つ資格。管理画面のアカウントとは別です |
| 設定版 | どの設定で確認・保存したかを区別する番号。古い画面からの上書きも検出します |
| 再送 | 通信切断などで同じ要求を送り直すこと。受理済みなら元の結果を返します |
| 非公開原本 | 受理した投稿と、その接続・処理情報を結び付けた、公開配信とは別の記録 |
| 保全 | 案件に必要な記録を、明示した期限まで別に保持する操作 |
| reader版 | 保存データを読むために必要な実装の対応版。製品バージョンやJSONのschemaとは別です |

## 基本機能

- Webと専用ブラウザで板一覧、スレッド一覧、スレッド閲覧、新規スレッド作成、返信を提供します。
- 一般利用者は匿名で投稿します。利用者アカウント、ログイン、有料機能は提供しません。
- 板の作成・設定、カテゴリー編集、管理者登録は管理者の操作です。一般利用者は板を作成できません。
- 投稿は確認画面・確認Cookieを通し、内容と公開条件を確認してから保存します。Web投稿は同一OriginとCSRF検証も必須です。
- 板・スレッド・投稿・設定・規制・非公開記録は永続保存します。保存結果が不確定なら成功を返しません。
- HTML・CSS・JavaScriptは同梱し、外部CDNやnpmビルドを必要としません。

## 投稿の流れと再送

### 通常の投稿が成立するまで

1. 利用者が板・スレッドと投稿内容を指定します。
2. サーバーが接続元の閲覧許可、投稿先の状態、入力、必要なCAP資格などを検査します。
3. 有効な匿名Cookieがなければ確認フローで発行します。クライアントがCookieを保持し、次の要求で返す必要があります。
4. 投稿内容と公開条件を確認します。確認の有効期間は10分で、内容・設定・規約に結び付けます。Webでは同一OriginとCSRFも検査します。
5. Cookie待機、投稿枠、条件規制などを検査します。確認後に設定が変わった場合は再確認を求めます。
6. 本文と非公開記録を結び付け、耐久保存の成立を確認します。
7. 確定した投稿を公開し、成功結果を返します。

確認・Cookie発行だけでは投稿は成立しません。CAP投稿も同じ検査を通します。

### 通信切断と重複防止

明示的な要求IDを使う場合、IDは投稿先・主体・内容に結び付けます。同じIDで内容を変更した要求は拒否します。受理済みの同一要求は、追加のレスを作らず既存の結果を返します。

保存途中のエラーや応答切断で結果が不明な場合は、内容と要求IDを変えずに再送します。再起動時には保存記録を照合します。

閲覧拒否へ設定が変わった接続元には、受理済みの再送も拒否します。元の投稿はその設定変更だけでは削除しません。

## 閲覧と専ブラ向け通信

### 公開URL

| 経路 | 内容 |
| --- | --- |
| `/`、`/{board}/` | サイトトップ、板トップ |
| `/bbsmenu.html`、`/bbsmenu.json` | 板メニューとカテゴリー |
| `/{board}/SETTING.TXT` | 板設定 |
| `/{board}/head.txt` | 公開ローカルルール |
| `/{board}/subject.txt` | スレッド一覧 |
| `/{board}/dat/{key}.dat` | DAT本文 |
| `/test/read.cgi/{board}/{key}/...` | Webスレッド閲覧 |
| `/test/bbs.cgi` | 専ブラからの投稿 |

### 文字コードと本文

専ブラ向け本文は固定の文字変換表を使う `sjis-compat-v1`、Web入力はUTF-8です。DATはETag、条件付き取得、HEAD、Rangeに対応します。

### 条件付き取得・差分・圧縮

公開配信はidentity（圧縮なし）、gzip、Zstandardに対応します。Brotli配信は提供しません。DATのRangeは圧縮していないDATのバイト位置を使い、有効な単一範囲をGETし、identityを許可している場合に差分を返します。保存用packやgzip・Zstandardの圧縮後バイト位置ではありません。

ETagは取得する表現に対応した値を使います。同じ本文でもidentity・gzip・ZstandardのETagを混同しません。保存の圧縮・整理だけでは、対応する表現の本文やETagを変更しません。

既存行の削除・置換後は、古いDATの末尾へ新しい差分を足す取得を成立させません。古い本文を持つクライアントは全文を取り直します。閲覧拒否の検査は304（本文を送り直さない応答）よりも優先します。

## 板・スレッドの設定

### 管理する項目

板の入力上限、名無し表示、ID・識別表示、スレ立てと返信の許可、スレ立てのCAP限定、ローカルルール、転載禁止、専ブラ閲覧専用を管理します。投稿設定を変更した後は新しい投稿に適用し、古い確認内容のまま送信された場合は再確認を求めます。

### 新規板の入力初期値

| 項目 | 初期値 |
| --- | --- |
| 名前の上限 | 96byte |
| メールの上限 | 64byte |
| 題名の上限 | 128byte |
| 本文の上限 | 4096byte |
| 本文の行数上限 | 60行 |
| 名前省略時の表示 | 名無しさん |
| 日ID | 必須 |
| ワッチョイ | 表示なし |
| スレ立て・返信 | 一般投稿を許可。Cookieや規制などの条件は別途検査 |

上限は正規化した入力を `sjis-compat-v1` で変換したバイト数で検査します。変換できない文字は数値文字参照にするため、見た目の文字数だけでは収まるかを判断できません。本文の行数は改行数＋1で数えます。最終DATの出力も別に検査します。板を編集した場合はその保存値を使います。

### 板とカテゴリーの件数

板は最大128、カテゴリーは最大256です。カテゴリー名・説明・所属・順序を管理画面で編集し、板メニューへ反映します。検索・対象展開を使って編集できます。

### スレッドのレス数と終了レス

新規スレッドのレス数上限は既定1000です。板で変更しても既存スレッドの上限は維持します。設定範囲は1〜10000件で、最初の投稿も通常レス数に含みます。

上限到達時の終了レス2件は、挿入の有無・名前・メール・本文を管理できます。初期状態は1件目のみ有効で、名前は `OimoBBS`、本文は「このスレッドは終了しました。」です。終了レスは終了時点の設定を使います。停止・アーカイブ・非公開・削除は別の管理操作です。

### CAPに限定する設定

CAP専用スレッドでは、返信時にも対象板の有効なCAP資格を要求します。本文・容量・規制・Cookie・確認の検査は維持します。CAP専用のスレ立て設定と、返信まで限定する設定は別です。

### 設定の適用時点

| 変更 | 反映する対象・時点 |
| --- | --- |
| 入力・投稿条件 | 変更後の投稿。古い確認内容なら再確認 |
| 板の新規スレッド上限 | 変更後に作るスレッド。既存スレッドの上限は維持 |
| 終了レスの内容 | スレッドが終了する時点 |
| 閲覧制限 | 新しい要求に加え、帯域待機後・送信片でも再検査 |
| 自動整理条件 | 次の整理バッチ |
| 待受・公開URL・証明書・保存先 | 起動設定を変更して再起動 |

## 匿名Cookie

### 必須になる投稿

Web・専ブラ・CAP・私的通報を含むすべての新規投稿で、有効な匿名Cookieを必須とします。Cookieなしでは確認フローで発行し、返送される前に投稿を保存しません。必須を解除する設定はありません。

### 有効期間・更新・失効

有効期間は30日で、残り7日以下では同じ内部IDのまま更新します。失効・期限・署名・世代を検査します。Cookie発行後の待機は0〜3600秒で設定でき、発行回数の制限、個別・全体失効を提供します。Cookie削除でIP側の利用枠や発行履歴はリセットしません。

### 秘密と内部IDの扱い

Cookie原文や再利用可能な署名値を公開・記録へ出しません。内部の関連付けには用途別HMACを使います。

## 投稿者の識別表示

### 公開表示と本人確認の違い

日ID、トリップ、CAP表示、回線・国・VPN表示は板設定と投稿資格に従います。公開ID・ワッチョイは本人確認や規制対象の主キーに使いません。

### ワッチョイの生成規則

ワッチョイは独自の `AABB-CCDD` です。各区画は用途を分離したHMAC-SHA256の結果をpaddingなしURL-safe Base64へ変換した先頭2文字です。

| 区画 | 入力 | 変化する条件 |
| --- | --- | --- |
| AA | 板UUID、週、IPv4 /24またはIPv6 /64 | 板、週、ネットワーク |
| BB | 板UUID、運営が指定するプロバイダキー | 板、プロバイダ |
| CC | 板UUID、検証済みCookie内部ID | 板、Cookie ID |
| DD | 板UUID、週、User-Agent分類 | 板、週、UA分類 |

週は日本時間の木曜0時からです。UA分類は括弧内コメントを除き、最大8個のproduct/majorを小文字化して使います。minorやOS・機種のコメントは入力に含めません。

### プロバイダキーと回線分類

プロバイダキーは表示名と独立した最大64byteの小文字英数字・`_.:-`です。同じプロバイダの複数範囲には同じキーを使います。固定回線の表示名は `ﾜｯﾁｮｲ` です。固定・携帯の両用途が確認済みの回線は「固定・携帯混在」（`mixed`）として扱い、投稿・閲覧の許可や条件規制で独立して選択できます。混在分類を保存した状態はreader85以降が必要です。分類表・ASN取得元・CIDR上書きを管理でき、未確認のIPから事業者を推測しません。

未設定サイトの初回サーバー起動では、[国内回線カタログ](networks.md)の国内204 ASN・VPN事業者/共有基盤7 ASNと国・日本・VPNの標準取得元を自動設定・取得します。取得元と回線カテゴリーはそれぞれ最大256件です。取得は最大8件ずつ、1回25秒以内で行い、全取得元の検査が成功した表だけを保存・配布します。失敗では前回成功表と手動上書きを維持します。共有上流・IPoEでは契約サービス名まで保証できません。

## 転載禁止と専ブラ閲覧専用

### 転載禁止

転載禁止は板単位で設定します。ローカルルール・投稿確認に案内を出し、robots、X-Robots-Tag、既知クローラーの拒否を適用します。

### 専ブラ閲覧専用

専ブラ閲覧専用の板はサイトトップと板メニューに表示します。サイト検索の板選択・結果から除外し、指定検索は404です。板トップは一覧・ローカルルール・専ブラ登録の案内を提供します。

専ブラ閲覧専用ではWebスレッド閲覧とWeb投稿を403で拒否します。UAやHTTPメソッド、Range、条件付き取得でも回避できません。DAT・subject・設定・ローカルルール・共通CGI投稿は維持します。クローラー制限も適用します。転載禁止の同意は独立した設定に従います。

### 閲覧制限との違い

| 機能 | 板一覧・メニュー | Webスレッド | DAT・共通CGI |
| --- | --- | --- | --- |
| 専ブラ閲覧専用 | 掲載を維持 | 閲覧・Web投稿を403で拒否 | 通常の許可条件に従って維持 |
| 接続元の閲覧制限 | 許可されない板を除外 | 許可されない接続を403で拒否 | 許可されない接続を403で拒否 |
| 転載禁止 | 公開案内に条件を表示 | 転載禁止の案内とクローラー制限 | 投稿確認とクローラー制限を適用 |

専ブラ閲覧専用でも、接続元の閲覧制限を免除しません。転載禁止と専ブラ閲覧専用はアクセス認証ではなく、DATの取得や利用者によるコピーそのものを防ぐ機能ではありません。

## 投稿規制と荒らし対策

### 組み合わせる規制

IP・ネットワーク・サイトの投稿枠、Cookieの発行・待機、IP/CIDR・本文・URL・Cookie・CAP・UAなどの条件規制を組み合わせます。条件規制は最大8条件のANDや許可例外を扱います。回線・国・VPNの許可は板別です。

### 投稿枠と超過時の応答

| 対象 | 補充・期間の初期条件 | burst（蓄積できる枠） |
| --- | --- | --- |
| IP別の返信 | 1件/秒 | 3件 |
| IP別のスレ立て | 1件/600秒、かつ61分に6件まで | 1件 |
| ネットワーク全体 | 60件/秒 | 120件 |
| サイト全体 | 200件/秒 | 400件 |
| IP別の投稿試行 | 10件/秒 | 20件 |

投稿試行には確認・失敗・再送も含みます。burstは短時間に使える蓄積枠で、すべての利用者へ常にその件数を保証するものではありません。板別・共通の設定と他の規制も検査します。枠不足は429と `Retry-After`（再試行までの待機）を返します。

### 共通設定と板別設定の関係

「掲示板全体の荒らし対策」で共通条件を初めて保存すると、投稿枠とCookie待機を全板へ適用し、新設板にも適用します。初回保存前は既存の板別設定を維持します。変更・無効化・再有効化で利用量をリセットしません。

### 類似文・埋め立て検出

追加の類似文・埋め立て検出は、無効・検出のみ・拒否を選べます。

| 条件 | 初期値 | 設定範囲 |
| --- | --- | --- |
| 類似文の期間 | 300秒 | 1〜600秒 |
| 比較する直近投稿 | 50件 | 1〜128件 |
| 類似度 | 90% | 50〜100% |
| 既存の類似投稿数 | 3件 | 1〜比較投稿数 |
| 近似比較の最低文字数 | 12文字 | 3〜1000文字 |
| 埋め立ての期間 | 30秒 | 1〜600秒 |
| 一スレッドの許容投稿 | 100件 | 2〜4000件 |
| 同一IPまたはCookieの許容投稿 | 30件 | 2〜4000件 |
| 占有判定の最低投稿 | 15件 | 2〜4000件 |
| 同一主体の占有率 | 80% | 50〜100% |

初期動作は検出のみです。類似文は空白を畳んだ文字3個の組に対するJaccard比で比較し、短文は完全一致を使います。認証済みCAPの追加対策免除を選べますが、既存の規制の免除には使いません。管理用検出一覧は直近100件で、再起動すると消えます。正常な定型文も検出し得るため、条件を管理者が調整します。

### 攻撃固有の規制によるCookie単位の停止

管理者が指定した攻撃固有のspam規制への違反を、Cookieごとに数えます。条件と停止範囲は次のとおりです。

| 項目 | 条件 |
| --- | --- |
| 停止の成立 | 固定60秒以内に、同じCookieの異なる要求で違反5件 |
| 停止の開始 | 5件目の違反記録を保存した時点 |
| 停止時間 | 600秒。停止中の違反で延長しない |
| 停止する投稿 | 対象Cookieによる全板の新規投稿 |
| 数える規制 | 空白除去後12文字以上の本文exact（完全一致）/contains（含む）、またはURL domain（ドメイン）条件 |
| 数えない規制 | 自動通報由来、IPだけ、短文・正規表現だけの規制、通常枠超過 |
| 再送 | 同じ違反要求は一件。受理済みの同一再送は既存結果を返す |
| CAP | 認証済みCAPは、この追加停止を免除 |

停止はCookie単位で、別Cookieの同じIPを巻き込みません。Cookieの作り直しや未知の攻撃文をすべて防ぐ保証はありません。

## 閲覧と投稿の許可

### 設定の適用範囲

閲覧設定は「掲示板全体」「板ごと」「管理画面のアクセス」の3つを独立して保存します。初期値はOFFです。板の閲覧には掲示板全体と板の両方の条件を満たす必要があります。管理画面には管理用の設定だけを適用します。

閲覧できない接続元は、スレッド作成・返信・CAP投稿・受理済み投稿の再送も拒否します。閲覧できる接続元にも、既存の投稿制限・Cookie・CAP資格の条件を適用します。投稿だけが禁止されている場合は閲覧できます。受理済みの投稿自体は閲覧設定の変更で削除しません。

### ローカルIP・自己IPの扱い

ローカルIP（プライベート・リンクローカル）と自己IP（ループバック）の閲覧許可は別項目です。許可・拒否・従来の回線条件に従うを選択でき、旧設定は従来条件のまま読み込みます。明示的な許可は回線・国・VPN・逆引き条件だけを免除し、IP/CIDR・クローラー・UAおよび掲示板全体の拒否は解除しません。

### 条件と判定の優先順位

| 条件 | 指定と判定 |
| --- | --- |
| 許可IP/CIDR | 空なら限定なし。指定した場合はリスト内だけ許可。最大256件 |
| 拒否IP/CIDR | 一致した接続を拒否。許可IPに含まれていても拒否。最大256件 |
| 回線種別 | 対象種別の許可・拒否。板別では板の手動分類も適用 |
| 登録国・日本限定 | 国分類表で判定。必要な表が未取得なら拒否 |
| 既知VPN | VPN分類表で判定。必要な表が未取得なら拒否 |
| 逆引き不可 | 逆引きによるホスト情報を取得できない接続の扱い |
| 既知クローラー | 対象のクローラーを拒否 |
| User-Agent | 大文字小文字を区別しない部分一致。最大64件、各256byte |

許可IPリストは入口の範囲を限定する設定です。その範囲に含まれていても、ほかの拒否条件を満たせば拒否します。

#### 判定例

| 条件 | 結果 |
| --- | --- |
| 全体が拒否、板が許可 | その板の閲覧・投稿を拒否 |
| 全体が許可、板が拒否 | その板の閲覧・投稿を拒否 |
| 全体も板も許可、投稿規制に該当 | 閲覧は許可、投稿は拒否 |
| 許可IPに含まれるが拒否CIDRにも含まれる | 拒否 |
| ローカルIPを明示的に許可、拒否UAに該当 | 拒否 |
| 国の条件を使い、必要な国分類表が未取得 | 拒否 |
| 管理用の条件だけが拒否 | 管理画面を拒否。掲示板は全体・板の条件で別に判定 |

OFFにした閲覧設定は、その設定内の条件を判定しません。他の閲覧設定、投稿規制、認証、専ブラ専用、クローラー制限まで解除する意味ではありません。

### 配信・一覧・送信中の再検査

Webの板・スレッド・投稿フォームと、専ブラのDAT・subject・SETTING・headを制限します。許可されない板はその接続元の公開板一覧・メニュー・検索から除きます。直接取得はGET/HEAD、Range、圧縮、304の応答でも403を返します。条件付きの公開応答は共有キャッシュへ保存させず、帯域待機後・各送信片でも許可を再確認します。配布済みのクライアント内コピーは回収できません。

### 管理画面の制限と復旧

管理画面のアクセス制限は、ログイン前の画面・API・資産も対象にします。許可CIDRを `127.0.0.1/32` に限定すれば、そのIP以外を拒否できます。判定対象は実接続元、またはmTLSで認証した公開入口が確定した利用者IPです。パスワードと既存のクローラー拒否を継続し、現在の接続元を拒否する設定の保存は422で防ぎます。

回線変更等で入れなくなった場合は、停止中CLIで管理用制限だけをOFFにできます。[解除手順](operations.md#管理画面のアクセス制限を解除する)に従い、掲示板の閲覧設定とパスワードは維持します。

| 閲覧設定の操作 | 必要な役割 |
| --- | --- |
| 掲示板全体・管理用の編集 | site_admin |
| 板別の編集 | 担当board_admin以上 |
| 板別の設定閲覧 | 担当board_admin以上 |

保存はCSRF・版比較・再送照会・監査を伴い、reader83以降を宣言します。reader82の旧閲覧設定も読み込めますが、新形式を保存した後は旧バイナリへ戻せません。OFFにしても保存形式は旧版へ戻りません。

## 管理者とCAP

### 管理画面の公開と認証

通常の管理画面は、掲示板と同じHTTPS Origin・ポートの管理パスで提供します。管理用の別ポートは開きません。直結構成と認証済み公開入口に対応し、後者もmTLSと実接続元の確認を管理要求に適用します。管理パスは公開のrobots.txtにも掲載せず、管理Cookieはその配下に限定します。公開ページにリンクを載せず、全応答の検索抑止、robotsの巡回禁止、既知クローラー403を適用します。管理データは認証後だけに返し、HTTPSの管理CookieはSecure・HttpOnly・SameSite=Strictです。

パスワードは15〜128文字です。保存はArgon2id v19、64 MiB、3回、並列度4、乱数salt16バイト、導出結果32バイトに固定します。照合は同時2件・待ち16件までです。PBKDF2の保存形式と照合は通常バイナリで受け付けません。

### 管理者の役割と追加権限

管理者の権限は「ロール」「担当板」「非公開情報の追加権限」で決まります。画面での選び方と操作の比較は[管理者の権限](admin-permissions.md)を参照してください。

| ロール | 画面の名称 | 操作範囲 |
| --- | --- | --- |
| `moderator` | 投稿・スレッドの管理担当 | 担当板の投稿削除・スレッド公開停止・投稿停止・自動通報の確認。追加権限は個別に付与 |
| `board_admin` | 板管理者 | 投稿管理、板設定・規制・ローカルルール・スレッド設定・アーカイブ・CAP資格の管理。担当板について全追加権限を含む |
| `site_admin` | サイト管理者 | 全板・サイト設定・板追加・管理者への権限付与・運用設定。全追加権限を含む |

ロールは `moderator < board_admin < site_admin` の順です。上位ロールは下位の操作も含みます。site_admin以外は担当板の範囲内に限り、担当板が空なら板を操作できません。site_adminは新設板を含む全板とサイト全体が対象です。

### 非公開情報の追加権限

投稿・スレッドの管理担当は板設定・スレッド一覧・操作記録を閲覧できません。操作対象を指定した削除・公開停止・投稿停止の確認画面は利用できます。追加権限を付与しても、この閲覧制限は解除されません。

管理ナビゲーション（PC・スマホ）、投稿管理画面の関連リンク、マニュアル内の管理画面リンクは現在のロール・追加権限に応じて表示します。権限のないリンクはHTMLに出力しません。再認証が必要な操作は、そのロール・追加権限を持つ管理者にはメニューを表示し、実行時に再認証を検査します。

追加権限は次の2項目です。moderatorには必要な項目だけを付与します。board_admin・site_adminには両方ともロールとして含まれるため、明示許可が空でも利用できます。

| 追加権限 | 画面の名称と許可する操作 |
| --- | --- |
| `private_reports.read` | 削除依頼の閲覧・回答。非公開の依頼本文・連絡先の閲覧と回答 |
| `evidence.manage` | 記録の閲覧・保全・出力。投稿原本・接続記録の照会、案件用コピーの保存・延長・解除、提出用ファイルの出力・ダウンロード、受け渡し履歴の登録 |

記録関連の操作は単一の許可で管理します。受け渡し履歴の登録だけで相手にファイルは送信されません。原本照会・保全・出力・受け渡し履歴の登録には原則として10分以内の再認証が必要です。再認証でも担当外の情報は取得できません。

### 権限の付与と保存

管理者画面とマニュアルは、認可・保存検査と共通の定義から3ロール・2追加権限を説明します。board_admin・site_adminでは追加権限をすべてチェック済み・変更不可にします。site_adminでは全板をチェック済み・変更不可にし、新しく追加した板も自動で担当します。ロールを下げた場合は、自動チェックを個別付与へ転用しません。

JavaScriptなしでも上位ロールの編集画面はチェック済み・変更不可になります。HTMLのsite_admin指定は担当板を空集合として保存し、APIの空でない担当板指定は拒否します。担当板の空集合はsite_adminに限り全板を意味します。実効追加権限はサーバーがロールから決定し、disabled入力が送信されなくても失われません。

上記の3ロール・2追加権限だけを受け付けます。未定義の名前はHTML/API/CLI・保存済みアカウント・変更receiptで拒否します。

更新すると対象管理者の認証世代が進み、既存セッションが失効します。最後の有効なsite_adminの無効化・降格は拒否します。公開配信と非公開記録の送信時には、現在のセッション・世代・ロール・担当板・実効追加権限を再検査します。

### CAPの資格

CAPは板への投稿・スレ立て資格です。管理者ログインとは別です。担当板、有効期限、停止状態、資格の世代を検査します。CAP名はトリップや認証秘密と分けて表示します。

### CAPの非公開管理コマンド

対象板のpost権限があるCAPは、返信フォームから次の非公開操作を実行できます。

| 入力例 | 操作 |
| --- | --- |
| `>>1 !ban 30m` | 対象レスのCookie主体を板内で30分拒否 |
| `>>1 !ban 2h`、`>>1 !ban 7d` | 2時間、7日拒否 |
| `>>1 !ban` | 永久拒否 |
| `>>1 !unban` | 対象主体の板内・手動Cookie完全一致拒否を解除 |
| `>>1 !delete` | 透明削除。レス番号を維持 |
| `>>1 !stop` | 現在スレッドの通常返信を停止 |

入力と対象には次の条件があります。

- 同じスレッドに存在するレス一件を指定します。複数対象は拒否します。
- 時間の単位は小文字の `m`（分）・`h`（時間）・`d`（日）の一つで、最大36,500日です。`1h30m` のような合成時間や、余分な理由の追記は拒否します。
- BANは保持中の署名原本から匿名主体を解決します。CAP・システム・主体欠測のレスは対象にしません。
- `!unban` は板内の手動Cookie完全一致拒否だけを解除します。IP規制などを一括解除する操作ではありません。

管理コマンドの本文は公開レスを作りません。不正なコマンドも通常投稿へ戻しません。公開中で期限内なら、通常返信の停止や上限到達後も管理操作を受け付けます。非公開・期限切れのスレッドは対象外です。

## 記録・削除・保持期限

### 公開削除と原本保管

公開削除と非公開の原本保管を分離します。レス削除でも番号を維持し、公開本文の回収と非公開原本の残存を別に管理します。

| 記録 | 通常の保持期限 |
| --- | --- |
| 受理済み投稿の非公開原本 | 確定から日本時間の6暦月 |
| 投稿試行・閲覧などの接続と処理結果 | 通常7日 |
| 未受理本文の一時保存 | 準備から24時間 |
| 案件の保全コピー | 明示した保全期限 |

### 期限の計算と削除後の扱い

6暦月は180日固定ではありません。日本時間で6か月後の同時刻を使い、その月に同じ日がなければ月末へ丸めます。例えば2026年8月31日12:00に確定した原本の期限は、2027年2月28日12:00です。

再送・閲覧で期限を延ばしません。公開削除で受理原本の保持期限を短縮しません。通常バックアップも本文の元の期限に従います。案件保全は明示した別の保全期限で管理します。

公開停止と各コピーの回収は別に管理します。保存上の順序は[削除と期限回収](architecture.md#削除と期限回収)を参照してください。

IPとポート、観測時刻、要求・接続情報、秘密除去済み入力、設定版、保存結果を署名記録へ結合します。取得不能・欠測は理由を付け、現在の設定から過去の観測値を補いません。

### 記録しない秘密と照会権限

Cookie全文、Authorization、管理パスワード、トリップ・CAP秘密、CSRF等は記録へ残しません。管理監査は操作の要約で、本文やIPの原本とは別です。案件の照会・保全・署名ZIP出力・受け渡しは、現在の権限と保持期限を検査します。

提出ZIPの `records.csv` は日時を日本時間（JST、`+09:00`）に統一し、同じ情報の重複列を省きます。配列内の日時も同じ形式です。単調時計の経過時間はナノ秒のまま残します。各列と欠測理由の読み方は同梱の `readme.txt` に記載します。署名検証用manifestの数値時刻と保存原本の形式はこの表示形式とは別です。

管理画面の「提出用ログ」から、架空の受理投稿・未受理・HTTP観測を収めたサンプルZIPを取得できます（`/evidence/sample.zip`）。サンプルは未署名の見本で、実データや案件は作成しません。取得には管理画面の認証が必要です。

## 運用と対応範囲

### 実行環境と起動方法

Linux、Go1.27.2、CGO無効、外部Go moduleはArgon2id用の `golang.org/x/crypto` とその内部依存 `golang.org/x/sys` に限定を前提とします。公開起動は既存サイトに対する `serve`、ローカル試験は永続型の `validation-serve` です。

### 保存形式と旧バイナリ

起動JSONの `schema_version` は1、サイト保存形式のschemaは2です。用途が異なるため同じ値に揃えません。未対応の保存形式や最低reader版は拒否し、自動的に古い形式へ変換しません。

### 設定変更と資源予算

板設定の「通報機能（!report）」で、板ごとに通報受付・自動停止の集計を有効／無効にできます。既存板は有効を引き継ぎ、サイト全体の起動設定が有効な場合に適用します。無効時の通常スレッドの `!report` は公開投稿となり、板別・共通の受付スレッドから対象板への新しい通報は拒否します。切り替えると対象板の集計を開始し直します。通報履歴と成立済みの停止期限は保持し、無効期間・切り替え前の票は再有効化・再起動で復元しません。保存は担当板の板管理者またはサイト管理者に限定し、reader84を宣言します。

帯域・キャッシュ・自動整理・通報条件は管理画面から変更できます。待受・公開URL・証明書パス・保存先などは起動設定です。通信予算は送信量の見積もりであり、実回線全体の上限保証ではありません。

検証手順は[検証方法](testing/README.md)を参照してください。

## WAF

[WAF](waf.md)は管理画面からON/OFFできる、初期OFFの追加要求検査です。パストラバーサル、秘密ファイル探索、未使用メソッド、URLやヘッダー内の既知攻撃パターンを処理前にHTTP 403で拒否します。投稿本文・認証情報と検索語は文字列検査から除外します。切り替えはサイト管理者の再認証・CSRF・版比較・再送照会・監査付き保存を伴い、稼働中と再起動後に反映します。大量アクセスには回線別・全体の頻度／瞬間集中／同時処理と検索専用枠を使い、緩めの初期値を管理画面で調整できます。超過時は429または503と再試行待ち秒数を返し、公開側と管理側の枠を分離します。新形式の保存後はreader87以降が必要です（旧reader86形式も読取り可能）。
