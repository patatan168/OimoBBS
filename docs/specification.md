# OimoBBSの仕様

現在の機能と共通ルールの概要です。導入は[セットアップ](setup.md)、掲示板の利用は[掲示板の使い方](user-guide.md)、日常管理は[管理画面ガイド](admin-guide.md)と[運用手順](operations.md)、実装の構造は[内部設計](architecture.md)を参照してください。

## まず押さえること

| 知りたいこと | 基本の動作 |
| --- | --- |
| 利用者の登録は必要か | ログイン不要です。投稿時は匿名Cookieと利用規約への同意を確認します |
| いつ投稿成功になるか | 投稿本文と非公開記録の保存が成立してから成功を返します |
| 管理者とCAPは同じか | 別の資格です。管理者は管理画面を操作し、CAPは指定板での投稿に使います |
| 設定変更はいつ効くか | 起動JSONは再起動後、管理画面の設定は保存後の対象操作に反映します。スレッド上限などは個別ルールがあります |
| あぼーんで原本も変わるか | 公開用データだけを削除表示に変え、非公開原本は書き換えません。原本の保持期限も短縮しません |

## 基本機能

- Webと専用ブラウザで、板・スレッドの閲覧、スレッド作成、返信を行えます。
- 一般利用者は匿名で投稿します。利用者アカウントやログインは不要です。
- 板の作成・設定、カテゴリー編集、管理者の追加は管理者が行います。
- 板・スレッド・投稿・設定・規制・非公開記録を永続保存します。
- HTML・CSS・JavaScriptは同梱し、外部CDNやnpmビルドを必要としません。

## 共通ルール

### 投稿・保存・再送

投稿確認やCookie発行だけでは投稿は成立しません。本文と非公開記録を結び付け、保存の成立を確認してから公開します。保存結果が不確定な場合は成功を返しません。

同じ要求ID・主体・内容の受理済み再送は、元の結果を返して重複投稿を防ぎます。同じIDで内容を変えた要求は拒否します。結果不明時は内容とIDを変えずに再送します。

### 投稿ログの提出

管理画面の「提出用ログ」から、保存済みの投稿・接続記録を保全し、全項目を含む署名付きZIPを取得できます。CSVは板キー・スレッド番号・レス番号、本人の本文と受理時の公開表示、保存済みの接続情報を含みます。終了案内などの自動投稿は含めません。日時は日本時間で、未保存の値は補いません。

[取得手順](admin-guide.md#提出用ログを取得する)と[CSV・署名の仕様](features/records.md#提出用ファイル)を参照してください。

### 設定の反映

待受・公開URL・保存先・証明書パスは起動JSONで指定し、再起動で反映します。稼働中の管理設定は保存後の対象操作に適用します。新規スレッドの上限は作成時、終了レスは終了時の設定を使います。[設定場所と反映時点](configuration.md#どこで設定しいつ反映するか)を参照してください。

### 資源と過負荷

公開本文・圧縮結果の保持量とHTML生成・圧縮の同時処理数は、CPU・メモリへ自動追従します。WAF、送信予算、受付列、メモリ予約、保存容量の条件も適用します。送信予算を増やしても実回線の速度は増えません。計算方法と受付を再開する条件は[CPU・メモリ・帯域の管理](features/resources.md)を参照してください。

### 保存容量と自動回収

公開起動では、新規投稿を止める最低空き容量を下回る前に、最終投稿から7日以上のスレッドを回収します。未満杯、満杯の順に最終投稿の古いものから処理し、DATと対象投稿の原本を回収します。保全中・固定・システム報告スレッドは除外します。対象や空き容量によっては新規投稿を止めるため、圧縮保存だけで容量不足を防げる保証はありません。[回収の条件と確認方法](features/records.md#容量不足時の自動回収)を参照してください。

## 実行環境と保存形式

| 対象 | 現在の条件 |
| --- | --- |
| ビルド | Linux、Go1.27.3、CGO無効 |
| 外部Go module | Argon2id用の `golang.org/x/crypto`、パスキー用の `github.com/go-webauthn/webauthn` と各内部依存。版は `scripts/go-dependencies.json` に固定 |
| 公開起動 | 作成済みサイトに対するHTTPSの `serve` |
| 永続型の検証起動 | `validation-serve`。ローカルHTTPと検証用HTTPS |
| 起動JSON | `schema_version: 1` |
| サイト保存形式 | schema 5。最低reader版も別に検査 |

保存形式と最低reader版の条件を満たさないバイナリは起動を拒否します。更新・切戻しは[運用手順](operations.md#バイナリ更新)、確認方法は[検証方法](testing/README.md)を参照してください。

## 用語

| 用語 | 意味 |
| --- | --- |
| 板 | テーマごとにスレッドをまとめる単位。URL用の板キーと内部の板UUIDを持ちます |
| スレッド | 題名と連続したレス番号を持つ投稿のまとまり |
| レス | スレッド内の一件の投稿。最初の投稿もレス数に含みます |
| DAT | 専用ブラウザへ渡す本文。名前・メール・日時と識別表示・本文・題名を行ごとに並べます |
| 匿名Cookie | 投稿資格と同一主体の関連付けに使う、サーバーが発行した署名付きCookie |
| 確認Cookie | Cookie使用・利用規約への同意をサイトと規約版ごとに保持するCookie。有効期間は1年 |
| CAP | 指定された板で特別な表示・投稿権限を持つ資格。管理画面のアカウントとは別です |
| 設定版 | どの設定で確認・保存したかを区別する番号。古い画面からの上書きも検出します |
| Origin | `https://bbs.example.com:8443` のようなscheme・ホスト・ポートの組。URLのパスは含みません |
| CSRF | 他サイトから利用者の意図しない更新を送らせる攻撃。更新時のトークンやOrigin検査で防ぎます |
| mTLS | 接続先だけでなく接続元の証明書も検査するTLS。公開入口と保存サーバー間の認証に使います |
| 再送 | 通信切断などで同じ要求を送り直すこと。受理済みなら元の結果を返します |
| 非公開原本 | 受理した投稿と、その接続・処理情報を結び付けた、公開配信とは別の記録 |
| 保全 | 案件に必要な記録を、明示した期限まで別に保持する操作 |
| reader版 | 保存データを読むために必要な実装の対応版。製品バージョンやJSONのschemaとは別です |
