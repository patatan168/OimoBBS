# 攻撃を混ぜた投稿検証と未受信本文の早期拒否

2026-11-02。`279ea66`を変更前として、既定WAFのまま正常投稿へ大量投稿と低速送信を混ぜました。拒否済み要求が本文の受信を待つ不具合を修正しました。[全試行・条件・判定・失敗記録](attack-mix-20261102.json)を保存しています。稼働環境は変更していません。

## 修正した経路

GoのHTTP/1サーバーは、応答前や要求終了時に未読本文を破棄することがあります。64KiBの本文を宣言して何も送らない要求では、429を決定しても約10秒の受信期限まで応答を返せませんでした。`Connection: close`だけでは、応答後の本文closeで接続が残る場合もあります。

`delivery.RejectUnreadBody`で、HTTP/1の本文付き拒否に接続終了と即時の受信期限を設定します。WAF403、頻度制限429/503、要求枠503、メモリ不足503、送信予算の失敗へ適用しました。本文のない要求とHTTP/2の接続再利用は維持します。受理した要求の受信期限・投稿制限・保存順序・Syncは変更しません。

公開中継の400/404/405/413/503にも適用します。保存側のエラーを転送する場合は、応答ヘッダーに接続終了を指定し、応答本文を読み終えてから利用者の受信を打ち切ります。保存側HTTP/2では、早すぎる打ち切りがエラー応答も中断し、遅すぎる打ち切りは応答Body.Closeの送信完了待ちを残すためです。転送失敗で応答本文を閉じる場合も受信を解放します。

## 再実行

```sh
mise exec -- python3 scripts/probe-thread-resources.py \
  --attack-mix --waf --image <検査するローカルイメージ> \
  --cpus 2 --memory 2g --egress-bps 80000000 \
  --output var/attack-mix.json
```

20投稿/秒の境界確認は`--attack-normal-rate 20`を追加します。出力は新規ファイルに限り、判定失敗でも結果を残して非ゼロ終了します。このモードは`--waf`必須で、WAF上限の上書きや他の負荷モードとの併用を拒否します。任意URLを指定する入口はなく、共通測定器が作る新規Docker volumeと自動割当のloopback TLSポートだけを使います。

通常運用では大量アクセス制限を有効にする必要があります。この試験は認証・CSRF・再認証・設定保存を通ってWAFを有効化し、保存後の値と秘密ファイルへの403を確認します。検証のために製品既定の上限を緩めません。

## 共通条件と判定

Go1.27.3、CGOなし、同じruntime image、2CPU・2GiB、送信予算80Mbps、共有ホスト・共有SSDです。変更前後を交互に実行しました。測定対象はBBSへ直接接続するHTTP/1.1の実HTTPSです。中継全体への攻撃混在試験は含みません。

| 入力 | 条件 |
| --- | --- |
| 正常投稿 | 通常5秒・攻撃12秒・回復5秒。既定10主体×各1投稿/秒、4スレッド、専ブラ80%・Web20% |
| Web | フォームCSRF取得、投稿、303遷移先のgzip復号まで実行 |
| 大量投稿 | 別IPで同じ確認済みCookieを8接続が共有。構文上正しい一意本文・要求IDを100要求/秒、12秒で1,200件予定 |
| 低速本文 | 別IPから16TLS接続、Content-Length: 65536のヘッダーだけ送信 |
| 低速ヘッダー | さらに別IPから64TLS接続、ヘッダー末尾を送信しない |
| WAF全体 | 毎秒300・瞬間600・同時128、同一IP毎秒60・瞬間180・同時32 |
| WAF投稿枠 | 毎秒60・瞬間120・同時32、同一IP毎秒10・瞬間30・同時8 |

正常主体は攻撃者と異なるIP・Cookieです。共有NATや多数IPによる攻撃を再現していません。大量投稿は規則違反文字列ではなく、確認済み主体による正しい入力を使います。

判定は正常投稿の全予定成功・未発行ゼロ、予定時刻からのp95が1秒以内、DATの準備時prefix・本文・名前・ACK全件・重複・ACKなし保存の照合、OOMなしを要求します。攻撃投稿は95%以上の発行と429、受理数が同一IPの瞬間枠30＋毎秒10×12.5秒以下であることを要求します。低速接続は16/64件すべての発行・終了、誤ACKゼロ、本文未送信の429が8件以上かつ全件1秒以内を要求します。低速側のクライアント待機上限13秒を、サーバーの切断成功へ数えません。

## 低速接続と回帰検査

低速本文16接続のうち8接続はWAF枠内に入り、従来どおり約10秒で切断されます。低速ヘッダー64接続は約5秒で切断されました。今回短縮した対象は拒否済みの残り8接続です。全低速接続を即時判定できる対策ではありません。429ヘッダー到着と実接続の終了は分け、実HTTP単体検査ではConnStateのClosedと処理枠の解放も確認します。

変更前の実TCP回帰検査は公開/管理×固定長/chunkedの4ケースすべてが2秒の待機上限で失敗し、修正後は通りました。公開中継も修正を外した隔離コピーでは保存側HTTP/1・HTTP/2の両方で応答が2秒以内に返りませんでした。

中継の初案は受信期限を応答ヘッダー時点で切り、race検査で保存側HTTP/2の応答がunexpected EOFになりました。次案の転送終了後の処理ではBody.Closeが送信待ちを残しました。goroutine stackで待ち先を確認し、最終版は応答本文の読取り終端で受信を解放します。失敗ログも残しています。最終版は実TLSで中継前拒否、保存側HTTP/1・HTTP/2の429全文転送、利用者側HTTP/2の別要求・同一接続維持をrace付き10回反復して通りました。

```sh
mise exec -- go test -race ./internal/publicedge -run 'TestEdge(Rejects|Relays|HTTP2|Stops)' -count=10
mise exec -- go test -race ./internal/publicedge ./internal/delivery ./internal/bootstrap \
  -run 'TestEdge|TestReject|TestRequestGate|TestDelivery|TestWAFIngress|TestWAFTraffic|TestMemoryRejects|TestMemoryAdmission|TestHTTPPathSecurityBoundary|TestProxy' -timeout=5m
mise exec -- go test ./internal/publicedge ./internal/delivery ./cmd/oimoedge ./cmd/oimobbs
mise exec -- go vet ./internal/publicedge ./internal/delivery ./internal/bootstrap ./cmd/oimobbs ./cmd/oimoedge
python3 -m unittest discover -s scripts -p 'test_probe*.py'
```

上記の最終検査、関連bootstrapの通常検査、Python20件、BBS・中継のbuildが通りました。定期セキュリティ検査にも新しい拒否経路と測定器の検査を加えました。今回、bootstrap全体の再実行、全パッケージのrace、fuzz、依存脆弱性検査は行っていません。

## 記録と未検証範囲

生イベント・全ログ・再実行スクリプト・変更前ソース・イメージ条件は`var/attack-mix-20261102/`です。JSON要約は最終判定関数で再計算しています。最初の20投稿/秒の3報告は、低速429の集計に大量投稿を混ぜた誤りだけを修正し、元報告を`.original.json`として保持しています。イベントと測定時間は変更していません。
