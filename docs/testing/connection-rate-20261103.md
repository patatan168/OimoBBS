# TLS前の新規接続頻度と攻撃混在の比較

2026-11-03。変更前は`f8fd49c`です。既存の同時接続数制限は、接続を閉じて作り直す場合の頻度を制限していませんでした。新規TCP接続をTLSの処理前に制限し、同時接続数を低く保った攻撃による暗号処理の反復を抑えます。稼働環境は変更していません。

## 変更と適用範囲

直結の公開口と公開中継に、新規接続の全体毎秒256・瞬間512、回線別毎秒16・瞬間64を適用します。別待受の管理HTTPSは全体毎秒32・瞬間64、回線別毎秒4・瞬間8です。既存の同時接続数・HTTP/2・受信期限は維持します。[上限と共有回線への影響](../features/resources.md#tls前の新規接続制限)を参照してください。

実socketのIPv4またはIPv6 /64をキーにし、接続を閉じても消費を戻しません。頻度記録は最大4096件で、完全に補充された回線を接続到着時の巡回で除去します。全体超過や記録数上限で拒否する新規回線は記憶せず、拒否を繰り返しても回復期限を延ばしません。待機列・専用タイマー・拒否ごとの保存ログは追加しません。

同時接続枠を内側で取得してから頻度を照合するため、同時接続枠で拒否した接続には頻度枠を使いません。TLSより前の拒否は接続終了であり、HTTP429とは別です。WAFのON/OFF・回線別制限とは独立して有効です。認証済み中継から保存側への集約接続とローカル管理トンネルは、従来の同時接続枠を維持します。

## 比較条件

Go1.27.3、CGOなし、同一のruntime image、2CPU・512MiB・swapなし、送信予算80Mbpsの隔離Dockerです。共有ホスト・共有SSDを使います。BBSへ直接接続するloopbackの実HTTPS HTTP/1.1を測り、WAFは認証・再認証・CSRFを通じて製品既定値で有効にします。回線情報の更新は停止していません。測定中はbuild・Go試験・別の負荷試験を重ねていません。

正常5秒・攻撃12秒・回復5秒です。正常20主体×各毎秒1投稿で440件、専ブラ80%・Web20%、4スレッドです。Webはフォーム取得・CSRF・投稿・303遷移先のgzip復号まで通します。攻撃者と正常主体のIP・Cookieは分離しています。

攻撃区間は構文上正しい一意本文の投稿毎秒100件×12秒・8接続、別IPの本文未送信16接続、さらに別IPのヘッダー未完64接続に、別IPからのTLS新規接続毎秒400回×12秒・16workerを重ねます。TLS攻撃側は確立後すぐ閉じ、HTTP要求を送信しません。1本ずつの接続寿命が短いため、同時接続数だけでは頻度を制限できない入力です。

変更前・候補を交互に各3回測ります。順序はbaseline r1→candidate r1→candidate r2→baseline r2→baseline r3→candidate r3です。変更前のimageは`e5e2ebe`から作成されたものですが、`f8fd49c`との差分は文書だけで、`cmd`・`internal`の差分がないことを確認しました。

正常投稿の全予定成功・未発行ゼロ・予定起点p95が1秒以内、DATのprefix・本文・名前・全ACK・重複・ACKなし保存の照合、OOMなしを要求します。従来の攻撃発行・拒否・低速接続終了の条件に加え、TLS攻撃の95%以上の発行、確立数264以下、クライアント期限超過ゼロを要求します。264は瞬間64＋毎秒16×12.5秒の上界です。変更前がこの追加条件で不合格になることも記録します。

## 確認の限界

単一IPからのTLS再接続に対するCPU削減を測る試験で、任意の攻撃中の正常投稿全件受理や最大投稿処理量の向上を保証しません。同じNATやVPN出口を多数の正常利用者が共有して毎秒16回を超えて新規接続する条件は未測定です。既存接続の再利用で回避できる制限ですが、新規利用者の通信を拒否する場合があります。

多数IPからの長時間攻撃、全体の新規接続枠を使い切る攻撃、新規利用者の優先受付、外部回線、OSの接続待ち行列・帯域飽和、実mTLS中継を通した攻撃混在負荷は未検証です。公開中継の共有部品とHTTP経路の回帰検査は、実配備構成全体の負荷検証には代えられません。bootstrap全体のrace、全パッケージ試験、fuzz、脆弱性DBによる再診断、稼働環境への反映は今回の対象に含めません。
