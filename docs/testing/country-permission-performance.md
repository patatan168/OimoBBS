# 国内事業者による国条件補完と性能測定

測定日：2026-11-08（日本時間）。閲覧・投稿と個別板の国条件補完を実装した直後を基準に、照合と設定読取を最適化しました。既存の事業者別呼称を追加する前後の比較ではありません。

## 動作の確認

- 国内事業者を確認できる接続元は、元の登録国が国外・不明でも閲覧・投稿の国条件でJPとして評価します。
- 板別・共通の事業者上書き、JP拒否、回線・VPN・逆引き・IP/CIDR・UA・クローラーの拒否を維持します。板の許可で全体の閲覧拒否を解除しません。
- 実HTTP/2のGET/HEAD、通常管理APIで保存した板別設定、専ブラ投稿・Web投稿、再起動後の投稿を検証します。
- 元の登録国と診断情報は変更しません。高速な属性判定との一致を検査します。

## 測定条件

- Go1.27.3、AMD Ryzen 5 5500U、回線表・国表とも4万prefix。
- サーバーはCPU 0,1、クライアントはCPU 2,3へ固定し、両プロセスのGOMAXPROCSを2に設定。サーバーの2論理CPUは同じ物理コアのSMT兄弟で、クライアントは別の物理コアです。
- loopback TLSの実HTTP/2、製品の`SiteWebHandler`で`SETTING.TXT`を取得。通常のWAF・認証入口を含む稼働サーバー全体の負荷試験ではありません。
- 16並行、5万要求、各条件5回、前後を交互に実行。計測対象の合計100万要求は全件200・HTTP/2・本文一致、エラー0。応答本文は全実行で同じ564 byte・同じSHA-256です。
- 本計測中は追加ビルド・回帰検査を起動していません。別枠のCPUプロファイル採取は回帰検査と並行しているため、速度の比較集計には使用していません。

## 変更と根拠

最初のCPUプロファイルでは、国条件の重複照合と根拠表示用CIDR文字列の生成を確認しました。また、SETTING.TXTでは板設定JSONの再解析がサーバーCPUの約31%を使っていました。

1. 許可判定には国・国コード・VPNだけを返し、診断用CIDRや説明文字列を生成しません。詳細表示・記録のAPIは従来どおりです。
2. 国内事業者を先に確認でき、VPNを許可している国条件では不要な国表の再照合を省きます。国・VPN条件を指定しない場合も照合を省きます。
3. 板別・共通上書きに事業者キーがあれば自動表の照合を省きます。空欄キーの補完、特殊用途、確認済みサービスの優先順位は通常分類と一致させます。
4. SETTING.TXT/head.txtの板設定読取に、既存のrevisionと元byteを照合する所有ワーカー用キャッシュを再利用します。更新・同revisionのbyte変更・破損・欠落を隠しません。

## 再実行と範囲

基準・改善後の試験binary、SHA-256、CPUプロファイル、全stdoutは`var/country-permission-perf/`に保持しています。試験binaryのSHA-256は測定データにも記録しています。次のツールは外部サイトに接続せず、専用の一時repositoryとloopbackサーバーだけを作成します。

```sh
python3 scripts/measure-country-permissions.py \
  --baseline var/country-permission-perf/baseline.test \
  --candidate var/country-permission-perf/candidate.test \
  --output var/country-permission-perf/recheck --requests 50000 --repeat 5
```

[単体測定](../../internal/bootstrap/network_country_benchmark_test.go)と[HTTP測定](../../internal/bootstrap/network_country_load_test.go)は試験binaryへ含めます。HTTP測定は`OIMO_COUNTRY_LOAD=1`の場合だけ実行します。通常のテストでは起動しません。

これは隔離したGET経路と許可判定の測定です。投稿経路は動作を検証しましたが、集中投稿の件数/秒やディスク同期性能は測定していません。WAN・実機・稼働ホストでの改善率を示すものではありません。
