# pack読取りの重複検証と一時配列の削減

2026-10-25。[前回の復号器最適化](zstd-decode-tuning.md)を両版に含めたまま、pack全体を見直しました。**問題になった129レスpackの1コア全復元は約45%、DAT全文読取りは約20%短縮しました。** 日本語・混合・高エントロピーの1000レスpackでも全復元は約34〜35%短縮しました。[全試行・プロファイル・検証結果](pack-read-efficiency.json)を保存しています。稼働サービスへの反映は行っていません。

## 以前の悪化の再確認

深さ定数化前と前回版を、1コア・同じCPU 10で短く交互に測り直しました。入力と処理ごとに別プロセスで400msを2回、前後往復を2組、各版8標本です。129レスpackの全復元は6.148→6.101ms、DAT全文読取りは3.899→3.824msでした。以前の約5%の悪化は今回は再現せず、その原因は特定できていません。

今回の変更前後比較は、前回版を基準にしています。古い記録の異なる試行を差し引いて削減率を出していません。

## 削減した処理

全復元では、各投稿をblock内と最後の`ValidateSnapshot`で二重に意味検証していました。投稿サイズ確認のためのJSON再生成とDATの文字コード検査も二度走っていました。全復元のCPUプロファイルでは、JSON quoteが約26%、Shift_JIS復号が約11%、制御文字の探索で約8%を使っていました。この129レス入力ではzstd単体より後段の比重が大きい結果でした。

block処理はCRC・JSON・索引を検査し、レコードを順に渡すiteratorへ変更しました。全復元は最終の投稿・行・origin配列へ直接格納し、全worker終了後に`ValidateSnapshot`で全投稿の意味を一度検査します。総展開予算はblock展開前に検査します。DATハッシュ・重複送信索引・監査要約の検証も維持します。

DAT読取りは、選んだblock内の全投稿を引き続き検証します。各行はblockの展開配列を一時的に借り、検証してから要求範囲を最終出力へ直接コピーします。投稿・行・originの中間配列と、行ごとの一時cloneを省きました。全復元で保持する行はcloneを維持し、展開block全体を結果へ残しません。失敗時は全workerの終了を待ち、部分結果を返しません。

文字コード検証は、UTF-8文字列を作る`textcodec.Decode`から、同じbyte列を受理する`textcodec.Valid`へ変更しました。ASCIIを8byteずつ読み、非ASCIIは従来と同じShift_JIS表・私用領域・半角カナ・0x80の条件で検査します。DATのNUL・CR・途中改行は、それぞれ`IndexByte`で探します。末尾改行・4つの区切り・文字コード・投稿の全意味検証を維持しています。新しい検証経路は旧実装との照合を追加しました。

zstdの復号器・保存形式・圧縮byte・CRC・worker上限は今回変更していません。WAL操作のDAT検証にも同じ検証専用経路を使います。

## 条件

AMD Ryzen 5 5500U、Linux amd64、Go1.27.3。1コアは`GOMAXPROCS=1`・CPU 10、4コアは`GOMAXPROCS=4`・CPU 4/6/8/10に固定しました。4コアは異なる物理コアです。共有ホストで、排他CPU予約とcgroup制限は設けていません。計測中に他のビルド・検証・性能試験は重ねていません。

入力・処理ごとに別プロセスで変更前→後、後→前の順に測定しました。各400msを2回、計4標本の中央値です。返却配列の確保・GCを含みます。総CPUは全threadのuser+system時間です。fixture生成と圧縮は計時外です。

129レスは以前の悪化確認で使った、繰返しの多い約525KBの合成DATです。追加の3入力は、従来の文章・混合・高エントロピー各1000レスDATから、投稿本文を含む意味検証可能なpackを保存Level 6で作りました。小さい対照入力は既存の2レスfixtureです。稼働データは使っていません。

## 検証と境界

文字コードの検証専用経路は、全1byte値・全2byte値、ASCII走査の境界、長い入力、fuzzで従来の`Decode`の受理・拒否と照合しました。DAT行の検査も従来の制御文字・区切り・復号による条件と照合しました。

CRCを修復した不正な保存DATが、要求範囲の外にある場合でも拒否する試験を追加しました。DATとそのハッシュを変えずに投稿のIPを不正にした場合も、全復元・範囲読取りで拒否しました。返却行・返却DATの書換えが入力packや別結果を壊さないことも検査しました。

cmd群とdomain・textcodec・store・app・evidence・disclosure・zstd圧縮/展開の通常試験、bootstrapの回線分類・pack再起動・保存先往復・容量予約・snapshot監査継続・本文引継ぎの選択試験が成功しました。変更した3packageのraceとvet、全製品のCGO無効ビルド、設計検査も成功しました。fuzzは文字コード612,458実行、DAT行855,805実行、pack2,518実行で、各30秒指定の試行が成功しました。実行結果は全記録JSONの`validation`に保存しています。

実HTTP、ブラウザ、実ディスクの性能、メモリ制限、継続負荷、稼働ホストへの反映は今回の範囲に含みません。復旧経路の機能試験と、実機・実負荷での復旧時間の測定は区別します。
