## 試した保存経路

準備記録の全検証・署名・圧縮・Writeが終わってから、Syncを別goroutineで実行します。その待ち中に、所有列で本文の完全検証・候補状態・圧縮blockだけを作ります。両方が終わって準備記録の耐久化を確認した後、本文WALをWrite/Syncし、従来どおり確定記録のSyncと公開へ進みます。

これは[以前の決定記録の準備を重ねた試作](posting-pipeline-optimization.md)と異なり、準備記録のSyncへ本文準備を重ねる方式です。同期回数は減らしていません。署名・CRC・JSONの完全検査、準備記録→本文WAL→確定記録→公開・成功応答の順序、保存形式version 2を保ちました。

対象は共有本文WALを使う8投稿以上・2CPU以上、正規frame合計256KiB以下の一群だけです。最大64frame・8MiB、受付・メモリ・ディスク予約を維持し、大きい入力や少量投稿・1CPUは従来経路へ戻します。検証済み候補は元の状態・header・writer・論理末尾へ束縛し、一度だけ確定できます。候補を作っただけではI/O、容量予約、論理状態の更新を行いません。
