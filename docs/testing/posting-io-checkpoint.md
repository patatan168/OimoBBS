## 保存保証と変更

成功条件は、proposal同期→本文の共有WAL同期→decision同期→公開/成功応答です。同期を省略して未永続データを成功にする変更はありません。

以前は共有WALを同期した直後、同じ本文を個別WALへ小さく書いていました。今回は共有WAL内の位置・長さ・CRCだけを保持し、checkpointで64KiBの作業領域を使って個別本文へ連結します。再読込みのCRCを照合し、全本文のSyncが成功してから共有WALを削除します。書込み・短い書込み・読込み・CRC・Syncの失敗では所有者を止め、復旧元を残します。本文をメモリへ溜める方式ではありません。

さらに、従来の「64batchごと」の区切りを「合計4,096frameまたは16MiBを超える前」に変えました。最大64frame/8MiBの一括保存は維持します。従来の64batch×64frameと同じ最大復旧件数で、少量batchの回数だけでは全本文を同期しません。復号時も全recordの対象数・frame数をそれぞれ4,096以内へ制限します。保持する範囲記述子も最大4,096件です。圧縮前の総frame長も、保存・復旧とも従来の最大512MiB以内に制限します。未反映の個別WAL block長は、反映完了まで専用の容量予約として残します。投稿要求の予約と区別し、投稿・pack・backup・証拠保存・緊急予備領域が全用途の合計予約を同じ関数で確認します。本文反映に失敗した場合も、この予約を先に解放しません。

バックアップ・pack切替・個別追記・正常終了では、未反映本文を全て書いて同期します。異常終了時は既存の署名・世代・位置・必須prefix検査を全対象で終えてから共有WALを再実行します。保存のフィールドやbyte形式は変えていません。
