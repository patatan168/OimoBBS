**保存同期の遅延増大を防げた結果ではありません。投稿速度・p95の一貫した改善も未確認です。** 今回の採用範囲は書き込み量の軽減です。入力によって圧縮率は変わり、全ての投稿で同じ削減率になる保証はありません。

## 変更

16件以上・64KiB以上の必須記録の独立一括追記では、4CPU以下の圧縮blockを8frameから16frameへ広げます。保存群は最大64frame・8MiBで、全符号化後に一度だけWrite・Syncします。5CPU以上では従来の8frame分割を保ちます。CPUの判定は`GOMAXPROCS`です。

正規frameのbyte・署名・CRC・連鎖とWAL保存形式version 2、proposal→本文WAL→decision→公開・成功応答の順序、実fsync、受付枠・メモリ/ディスク予約は維持しています。非必須ログの保存方針も変更していません。

32frame・大きな繰返し本文の既存fixtureでは、16frame分割の保存量が8frame分割より約1.6%増えました。これも記録し、全入力での縮小を前提にしません。4CPUの合成64frameの単体比較では16frame分割が8frame分割より速く、保存量も減りました。32frame分割はその単体比較の4CPUで遅く、採用しませんでした。単体結果は実HTTPの改善率へ読み替えません。
