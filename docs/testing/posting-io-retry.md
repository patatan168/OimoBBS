## 単独WAL記録の圧縮

単独frameを圧縮する最小長だけを32KiBから1KiBへ下げた試作です。圧縮して小さくならない場合は元の形式へ戻します。正規frame・署名・CRC・保存形式version 2、実Sync、準備記録→本文WAL→確定記録→公開の順序を保ち、受付・メモリ・ディスク容量の上限も変えていません。

## 非必須ログの保存許可後の再収集

従来は非必須HTTPログを集めてから投稿I/Oの優先制御を待つため、待機中に行が増えても小さいbatchのまま保存する経路があります。最初の20msの収集は保ち、許可後に到着済みの行だけを待機なしで追加する試作を作りました。FIFO、最大256件・元JSON4MiB、保存中も含む4,096件・16MiBの予約、取消・欠測集計、投稿優先と非必須保存の飢餓防止を維持しています。単独WALの圧縮条件は基準版のままです。

25msを加える同じ診断条件で基準→再収集を各一回比較しました。ここでは主負荷を担当したプロセスの正常停止後・再起動前に欠測集計を保存し、後のプロセスの集計と分けています。保存件数には準備と回復の要求も含みます。
