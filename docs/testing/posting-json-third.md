# 投稿JSONの型検査と復号の統合

2026-10-25。直前の`ad00320`を基準に、JSONの構文検査と型付き復号の重複走査を減らしました。[前段の改善](posting-json-second.md)に続く変更です。[全試行・ソース・検査結果](posting-json-third.json)を保存しています。稼働環境は変更していません。

## 実装と入力契約

保存structの構文・Unicode・重複キー・完全なキー集合・null・数値範囲を同じ走査で照合します。独自復号器とmap等の標準復号は、本文全体の検査が成功してから非公開の候補へ適用します。末尾の不正な入力で独自復号器を起動せず、失敗した候補を呼出元へ公開しません。

通常サイズの省略可能boolも同じ走査で補い、キー選択・本文複製・再走査を省きます。正規化後サイズが上限に近い場合、既存値のmerge、特殊タグ、対応しない型は従来経路を使います。指定した最上位boolだけを補い、入れ子の必須項目は省略できません。

sliceは保留した独自復号の要素アドレスを固定するため、要素数を事前検査して一度だけ確保します。RawMessage・独自復号器・mapの内部にも、深さ16・Unicode・重複キー検査を適用します。sliceや独自型の内部では追加の走査が入ります。旧復号処理は差分比較用のテストへ移しました。保存形式、署名、fsync、投稿の確定順序、受付枠は維持しています。

## 検証と適用範囲

JSON・domain・投稿・evidence・store・appのrace、旧復号との差分fuzz4対象、全go vet、生成一致検査、CGO無効buildが成功しました。入力の切断・区切り・数値境界・Unicode・重複・未知キー・必須キー・サイズ上限・64件を超える独自復号・入れ子sliceも照合しています。詳細は[検査記録](posting-json-third.json)にあります。

検査を修正し、捕捉予約の解放を先に確認してから、所有処理列で本文を同期保存し、最後に全用途の予約が0になることを確認します。対象2件は各10回と関連raceが成功し、修正後の全Goテストも成功しました（31件スキップ）。
