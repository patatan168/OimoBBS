# 周期保守による停止連鎖の回避

2026-10-27。[前回の混合負荷](posting-cpu-lanes.md)で起きたWAF混雑応答と閲覧の未発行を対象に、`d176b10`から周期保守の投稿列待ちを修正しました。[全試行・診断・検査・ソース識別](posting-maintenance-stalls.json)を保存します。生データ、凍結ソース、実行コマンドは`var/posting-backpressure-20261027/`です。稼働サービスは置き換えていません。

## 原因と修正

前回の候補版は投稿42件が失敗し、閲覧398件が未発行でした。別の試行では基準版にも投稿51件の失敗、投稿2件・閲覧424件の未発行がありました。WAFの混雑応答を返した要求と同じ時期に、DAT・Web・subjectの読取りが数百ms〜約1秒待たされていました。

周期処理の`SweepExpiredControl`と監査移管は、サイト共通ロックを取得したまま板の処理列へ投入し、先行投稿の終了を待っていました。閲覧・別の投稿も板参照の共有ロックを取れず、実行中のHTTP要求が溜まる構造です。前回の最大120投稿主体＋40閲覧主体に対し、WAFの全体同時枠は128件です。閲覧の生成器は、各主体の予定が100ms以上遅れると未発行を記録します。閲覧の未発行は、サーバーの拒否件数とは別の値です。

投稿列を意図的に停止した回帰試験では、修正前の期限回収・監査移管・必須記録チェックポイント・未受理原本・carry回収の探索が、いずれも投稿列を解放するまで戻りませんでした。修正後は混雑板を次の巡回へ回します。制御行の回収は、同じ巡回でサイトの満了行を削除しても、延期分がある`More`を維持します。空いた後の巡回で板の満了行が削除されることも確認しています。

周期のスレッド監査移管はreader28の導入済み保存先だけで動きます。毎回の形式再有効化に伴う全板の制御監査・snapshot前照合を繰り返さず、対象スレッドの署名・日別receipt・削除台帳の照合を行います。明示的な形式有効化、制御snapshotの監査移管完全照合、明示の制御行回収・監査移管は従来の入口を維持します。

WAF設定、同時枠、頻度枠、HTTP受理枠、投稿のSync・公開順序は変更していません。保守は無効化せず、投稿列の空きがある巡回で再開します。混雑が続く間は保管行の回収が遅れますが、有効期限の延長や、署名・空き容量・公開条件の検査省略は行いません。保守を開始した後の保存・失敗・再開の規則も維持します。

全体枠128件のうち投稿120件を保持する受付・参照処理の試験も追加しました。旧経路では閲覧8件が共通ロックで止まり、9件目が503になります。修正後の周期経路では同じ要求が204で完了し、過負荷カウンタも増えません。これは停止連鎖を制御して再現する試験で、前回の個々の失敗要求について拒否カウンタを保存していたことを意味しません。

初回の修正版でも投稿18件、閲覧21件が失敗し、閲覧63件が未発行になりました。未受理原本の有無を調べる毎分探索にも同じ投稿列待ちが残っていたため、期限保守全体の停止試験を追加し、この探索も混雑時には延期するように修正しました。不完全だった試作の結果を最終版と分けて保存します。

## 比較条件と結果

通常ディスク・4CPU・GOMAXPROCS=4・4GiB、同一板16スレッド、120投稿主体・40閲覧主体です。30秒間に投稿4,800件（80%専ブラ・20%Web）と閲覧12,000件（DAT・Web・subject）を予定する実TLS HTTP/1.1試験です。前回の生成器・予定遅延による未発行判定をそのまま使用し、負荷を下げたり、WAF枠を広げたり、失敗した要求を自動再送したりしていません。

診断版には拒否箇所・保守の所要時間とCPU・mutex・blockの採取だけを追加し、通常版と分けます。ビルド・検査・プロファイル解析を負荷測定と重ねません。主負荷のCPU/I/Oは初期化、回復100投稿、最後の非必須HTTPログdrainを含みません。混合負荷のCPUを投稿数で割った値には閲覧の処理も含まれるため、仕事量が違う失敗試行とのCPU単価から高速化率を出しません。

診断版4回は別にJSONへ記録しています。通常版と合わせた全9試行で、受理済み投稿の欠落・余分な保存・重複、DAT本文・名前の不一致、OOM killはありませんでした。各回の負荷後100投稿が成功し、正常再起動後の16スレッドのDATとETagも一致しています。

## 検証と境界

投稿列の停止試験と、延期後の期限回収の再開、明示・周期の両方の監査移管についてintent・entry・receipt・ledgerの中断、再起動、重複防止、元本文の非公開、制御snapshotとの整合を検査しています。関連するrace、WAF・投稿保存・停止点の通常試験、全製品go vet、文書リンクとdesigncheckが成功しました。

追加した周期移管の試験はreader28導入済みの保存先が対象です。最初のfixtureは公開本体回収のreader27までだったため対象外となり、明示的にreader28を導入する準備へ修正しました。このfixture修正前の失敗も検査ログに残します。

長期・本番負荷、WAN・実NIC、電源断・媒体故障、追加の実HTTP SIGKILLはこの試験の対象外です。任意の過負荷で拒否をなくす保証ではありません。
