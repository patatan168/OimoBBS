# 投稿の並列準備とスレッド別候補索引

2026-10-25〜26の隔離測定です。投稿候補の無関係なスレッド走査と、必須記録準備の二度目のworker起動を削減しました。大幅なHTTP処理量の改善は確認できていません。[全56試行・ソースと測定資料の識別情報](posting-multicore.json)には、遅い試行、不採用候補、診断を含めています。その後の[稼働反映](posting-waf-deployment.md)は別に記録しています。

## 採用した変更

- 投稿バッチにスレッド別の候補索引を持たせ、再送照合、元状態の照合、本文保存で他スレッドの候補を走査しないようにしました。全体の保存順序は従来通りです。
- 必須記録の並列Buildとpayload検査に続けて、同じworkerでsource検査・hash・Base64を準備します。二つの並列区間の待合せを一つにしました。payload・総量・sealのエラー優先順を維持しています。

署名検証、順序付きchain、保存のSync、メモリ予約、受付制限は維持しています。非同期検証や保存形式の変更は採用していません。最終測定版には[入口WAFの変更](waf-ingress.md)も含むため、HTTP差分をこの二変更だけの効果とは扱いません。

## 比較条件

基準はコミット`117d613`。同じ実行環境の通常版と診断版を分け、Go1.27.3、CGO無効で構築しました。AMD Ryzen 5 5500Uの共有ホスト、共有ストレージ、隔離コンテナのCPU quotaを使っています。専有コアではありません。

固定件数試験は4GiB、80Mbpsのアプリ帯域予算、1板16スレッド、120 actor、従来形式80%・Web投稿20%、8,000件を1,600件/秒で予定し、全完了まで待ちます。Webではフォーム・CSRF・確認・303後の表示まで通ります。WAFは有効で、頻度だけを試験用の高い値にしています。内部の受付・作業予約・同時処理上限は維持しています。

CPU時間は投稿計時区間のコンテナ総CPUを成功件数で割った値です。起動・準備・追加回復投稿・終了後の残作業を含む全プロセスCPUではありません。処理量は予定5秒間だけの件数ではなく、完了待ちを含む経過時間で計算します。通常計時とビルド・Goテスト・profile解析は重ねていません。

## 投稿・閲覧の同時負荷

4CPU・4GiB、投稿160件/秒＋閲覧400件/秒を60秒、別の閲覧用1,000投稿fixture、8Gbpsのアプリ帯域予算で各版1回比較しました。実WANや8Gbpsの物理回線試験ではありません。

非必須HTTPログについては、正常再起動後の最終プロセスで17件受付・0件保存・17件失敗を記録しました。基準・試作・最終版で共通して発生しており、必須投稿記録の成功とは分けています。この集計だけでは失敗理由を確定できません。SIGKILL時の非必須ログも全保存は保証していません。

## 不採用候補と診断

`candidate`はcapture検証を構築workerへ移し、`partition`は索引と必須記録準備の統合を加えた版です。`pipeline`は構築完了と検証完了を分け、同じ有界poolで検証を進める版、`adaptive`は1CPUと独自validatorで従来経路を使う版です。いずれも採用していません。

非同期検証には予約1件だけの競合・並行投稿・破棄・race・復旧の検査も追加して試しました。しかし約3KiB本文4,000投稿の比較は666.9→672.3投稿/秒に対しCPUが4.709→4.755msとなり、同時閲覧では遅延と失敗を解消しませんでした。複雑化に見合う改善を示せず、最終版から取り除いています。試作の1/2/4/8CPU結果は最終版と区別してJSONへ保存しています。

診断版の基準4CPUでは26.72秒のCPU sample中、並列worker等を除いた投稿所有列の該当区間は約1.84秒でした。これは全待ち時間の割合ではありません。通常版の大きな経過時間変動に対して、CPUだけで原因や改善幅を断定しません。profile付き試験も通常版の中央値には混ぜていません。

## 強制再起動と検査

最終版を1GiB・2CPUで起動し、1,000件ACK後にコンテナへSIGKILLしました。同じ保存領域から再起動し、DAT1,001行・本文byte列・ETagが一致しました。SIGKILLから照合まで3.078秒、起動開始から2.969秒でした。保存済みWAF設定による遮断も再確認し、OOMはありませんでした。電源断・媒体障害・本番ホスト復旧を実証する試験ではありません。

通常テスト、投稿・必須記録・保存のrace、WAF/HTTP境界のraceとfuzz、vet、生成コード照合、CGO無効ビルドを検査しています。通常テストでは環境変数が必要なブラウザー・外部feed・資源診断等はskipされ、一覧と理由をJSONに残しています。実行コマンドと結果はJSONの`checks`を参照してください。元資料はローカルの`var/posting-multicore-20261025/`にあり、JSONにSHA-256を記録しています。
