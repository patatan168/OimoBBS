以下はPython実装時点の検証記録です。現行の実装・コマンド・検証結果は[Goへの統合](sealed-backup-go.md)を参照してください。ここに記載するPythonファイルと試験はGo版へ置き換え済みです。

2026-11-03。ホスト側の `tools/seal_online_backup.py` に、完成記録の安全な置換と、中断した出力の再作成を追加しました。稼働環境は変更していません。

## 再現した問題と変更

旧処理では完成記録のJSONを最終ファイルへ直接書き、次回はファイルの存在だけで完成済みと判定していました。JSON書込みの途中で止まると、壊れた記録を転送へ渡したり、期限回収時のJSON読込みで処理が失敗したりします。完成記録だけ残って暗号文が欠けた場合も、暗号化を再実行しません。

変更前の実行で、壊れた完成記録・暗号文欠落・JSON書込失敗の3試験がすべて失敗することを確認しました。

現在は次の順序で設置します。

1. 再作成が必要な場合、古い完成記録を除去してディレクトリを同期する。
2. 暗号文を一時ファイルへ保存・同期・Closeし、最終名へ置換してディレクトリを同期する。
3. SHA-256を計算し、完成記録を別の一時ファイルへ保存・同期・Closeして置換する。
4. ディレクトリを同期してから、完成報告・任意の転送へ進む。

古い完成記録を先に無効にするため、新しい暗号文の設置後に停止しても、旧暗号文のhashと組み合わされません。完成記録の置換後にディレクトリ同期が失敗した場合は成功・転送を止め、次回に再同期します。

この変更時点の再実行では、完成記録の構文・名前・期限・復元可否・hash表記と、空でない暗号文ファイルの存在を確認していました。不足があれば、Dockerの完成ログに残る未期限切れのコピーを再検証してから再暗号化します。続く[復号・転送再試行の強化](sealed-restore-resilience.md)で、既存暗号文の全体hash照合と、不一致時の再作成を追加しました。秘密鍵による復号検証は暗号化ホストでは行いません。

所有排他の取得後、中断した既知の一時ファイルだけを除去します。完成ログが消えた場合も一時ファイルを次回へ残しません。期限切れの完成記録・暗号文の除去後もディレクトリを同期します。元の保持期限は変更していません。

| 条件 | 確認した結果 |
| --- | --- |
| 壊れた完成記録・不正メタデータ・暗号文欠落 | 再作成し、完成した組だけを転送する |

この試験では保存先に実ファイル・実fsyncを使います。SIGKILLはJSON書込中の子プロセスへ実行しました。Dockerのログ取得・暗号化コマンド・scpは差し替えており、暗号文相当の固定byteを保存しています。ENOSPC・EIOは注入で、実ディスクを満杯にしていません。

併せて、`internal/sealedbackup` と `cmd/oimoseal` の既存試験、store/app/bootstrapの共有WAL復旧・復旧中の停止・容量予算・作成復旧に該当する既存試験が成功しました。今回のPython補助処理と実Docker暗号化を組み合わせた試験、実scp転送、電源断、実媒体故障、別ホスト喪失からの復元は未検証です。

## さらに強化できる箇所

この調査時点のCLIヘルスチェックはトップページ取得を使うため、板の保存停止を検知しきれませんでした。隔離したHTTPハンドラーで、板の停止状態を所有workerから設定したところ、トップページは200、当該板の `subject.txt` は503でした。診断の出力は同じ原出力ディレクトリの `health-gap.txt` にあります。実Sync失敗からの注入ではなく、停止状態を設定した経路確認です。この問題には続く[保存停止のヘルスチェック](storage-healthcheck.md)で対応しました。自動再起動の方針は変更していません。

ホスト・媒体の喪失については、別ホストへの保管と、最新の削除・期限情報を維持する隔離復元の定期検査が次の候補です。実環境の保管先・監視設定は今回確認していません。
