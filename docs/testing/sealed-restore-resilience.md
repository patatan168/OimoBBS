# 認証復号の途中停止とバックアップ再送の耐性

以下のPython部分は当時の検証記録です。現行の暗号化・送受信・期限回収とその試験は[Goへの統合](sealed-backup-go.md)を参照してください。Goの認証復号処理は引き続き使用しています。

2026-11-03。`0395979` の後に、復号結果の最終名への設置、保存済み暗号文のhash照合、Dockerの完成ログから独立した転送再試行を強化しました。稼働環境・別ホストは変更していません。

## 復号結果を完成してから設置する

旧 `oimoseal open` は最終出力名へ直接書いていました。通常の認証失敗では部分出力を削除しますが、SIGKILLではその処理が走らず、全体の認証を終えていない平文の先頭が最終名で残ります。旧処理に対する試験で、書込中の最終名の存在、同名競合の未検出、SIGKILL後の部分出力をそれぞれ再現しました。

現在は、0600の一時ファイルへ変換し、認証・Sync・Closeの成功後だけ、hardlinkで最終名を排他的に作成します。既存名があれば置換しません。一時名を除去してから親ディレクトリを同期し、最後まで成功した場合だけ正常終了します。鍵生成ディレクトリの親も同期します。暗号形式・認証方式は変更していません。

出力名ごとに0600の空のlockファイルを保持し、flockの非待機排他を使います。同名の処理が動いていればエラーとし、別名の出力は止めません。SIGKILLではOSが排他を解放するため、次の同名実行で残った一時ファイルを除去・同期できます。設置済みの最終名と一時名が同じinodeを指す中断状態も、一時名だけを除去します。通常ファイルでない一時名、権限や所有者の異常、リンクされたlockは使いません。

書込・短い書込・Sync・Close失敗では最終名を作らず、一時出力を削除します。書込とCloseの同時失敗も両方返します。最終名を設置した後の親同期失敗では、完全なファイルを残してエラーを返し、同名を勝手に上書きしません。入力が正しいことと、名前の設置が永続化したことを分けて扱います。

### 実バイナリの停止と再実行

CGOなしの `oimoseal` で、合成tarを暗号化しました。復号プロセスへ暗号文の先頭半分だけを送り、64KiB以上の認証済み平文が一時ファイルへ書かれたところで実SIGKILLしました。

| 条件 | 結果 |
| --- | --- |
| 復号途中のSIGKILL | 終了はsignal 9。最終名なし。一時ファイルは0600 |
| 同じ最終名で完全な入力から再実行 | 正常終了。旧一時ファイルも回収。583,680byteのtar全文とSHA-256が元と一致 |
| 復号したtarの読出し | 合成の `fixture.txt` が元のpayloadと一致。最終ファイルは0600・link数1 |
| 認証終端の改変・切詰め・余分な末尾・鍵違い | 各終了コード1。最終名なし |

Go試験では、保存障害・排他的設置・同名と別名の並行実行・不正な回収対象の拒否も確認しました。実SIGKILLは同じOSのpage cacheを維持する試験であり、電源断を再現したものではありません。

## 保存済み暗号文のhashを再確認する

旧処理は完成記録のhash表記と暗号文の存在だけを調べていました。同じ長さで1byteを反転した暗号文と、1byteを切り詰めた暗号文の両方を再作成せず再利用することを再現しました。

現在は、再利用・転送前に暗号文全体のSHA-256を完成記録と照合します。不一致なら、完成ログに残る未期限切れの元コピーを検証してから再暗号化します。再暗号化やhash読込みのI/Oが失敗すれば転送しません。元の完成ログがない不正な組も、再作成できたと推測せずエラーにします。同じ実行で確認済みの出力は、転送段階で再びhashを計算しません。

既存の暗号文を読む量は保存量に比例して増えます。これは新しい全体照合の費用で、投稿性能や共有ディスクへの影響は測定していません。暗号化ホストへ復号秘密鍵は渡さず、hash一致を秘密鍵による認証復号と同一には扱いません。

## ログが消えても既存コピーを再送する

以前はDockerの完成ログを処理するループの中でだけscpしていたため、転送失敗後にログが回転すると、残っている有効な組を再送しませんでした。Dockerのログ取得自体が失敗した場合も、既存出力へ進みませんでした。

転送は保存済みの完成記録からも再試行します。期限を確認し、hashを検証した組だけを転送します。ログ取得を30秒で打ち切り、取得が失敗しても既存コピーの転送・期限回収へ進みます。最後には元のログ取得エラーを返すため、新規コピーの暗号化まで正常だったとは報告しません。保持期限を延長する変更はありません。

Pythonの19試験が成功しました。改変・切詰め後の再作成、再作成失敗時の転送抑止、hash読込み失敗、転送timeoutからログ回転後の再試行、Dockerログの失敗・timeout・実行ファイル欠落後の既存コピー転送を含みます。保存先は実ファイル・実fsyncを使い、Dockerとscpは差し替えています。実際のSSH転送は行っていません。
