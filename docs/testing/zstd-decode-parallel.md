# Zstandard保存frameの並列展開

2026-10-25。比較元は`5062131`。独立したpackブロックの展開・検証を最大4workerで分担します。4CPUの単体測定では、8frameの展開が約2.2〜2.8倍、packのDAT全文読取りが約2.1倍になりました。[全標本・総CPU・割当・不採用試行](zstd-decode-parallel.json)を保存しています。稼働サービスへの反映は行っていません。

この記録は並列化段階の比較です。後続の単一frame内の処理削減は[Zstandard復号の計算と割当の削減](zstd-decode-efficiency.md)を参照してください。

## 適用範囲

`DecodePack`と`ReadPackDAT`で、対象ブロックが複数あり展開長の合計が128KiB以上の場合に分担します。呼出元を含め`min(4, GOMAXPROCS, 対象ブロック数)` worker、補助workerは全要求共通で最大`min(3, GOMAXPROCS−1)`です。補助枠を待たず、空きがなければ呼出元で進めます。実行途中にCPU上限が縮小した場合、既存workerの終了後から新しい上限を適用します。

索引の長さ・範囲・総展開予算を先に検査し、workerは重ならない出力範囲に書き込みます。全workerが終了してから結果を返し、失敗時は部分結果を返しません。複数エラーは元のブロック順に選びます。DAT範囲読取りは要求と重なるブロックだけを処理します。ブロック内の配列も検証済み件数で確保し、appendによる拡張を減らしました。

単一frameの復号器と圧縮byte、保存形式、保存・展開CRC、署名の扱いは変更していません。WAL・管理snapshot・回線分類データの単一frame展開にはこの並列化を適用しません。HTTPの配信圧縮や、受信側クライアントのzstd展開も別の処理です。

## 条件

AMD Ryzen 5 5500U、Linux amd64、Go1.27.3。共有ホスト上で測定し、CPU・メモリのcgroup制限は設けていません。測定中は他のビルド・検証・性能試験を重ねていません。`GOMAXPROCS=1/2/4`を環境変数で固定し、設定ごとに別プロセスで実行しました。割当・GCを含みます。総CPUは全threadのuser+system時間です。

8frame比較は同じ3種類の合成1000レスDATを保存Level 6で圧縮し、それぞれ独立した8つの入力配列を用意したものです。両CRCとzstd展開を含み、JSON検証を含みません。各条件300msを3回、同一プロセスで逐次→workerの順に測った中央値です。一般的なファイルや辞書付きframeへの速度保証ではありません。

pack全体は同じ129レス・約525KBの合成DATを保存Level 6で圧縮した入力です。本文は繰返しの多い文章で、zstdの展開に加えJSON・投稿・索引・DATハッシュ等の検証を含みます。変更前→後、後→前の順で各300msを3回、合計6標本の中央値です。

## zstd展開と両CRC検証

8frame合計の経過時間です。速度比は同じCPU設定で逐次処理と比較しています。

| 入力 | 1CPU 逐次→worker ms | 2CPU 逐次→worker ms | 4CPU 逐次→worker ms | 4CPU速度比 |
| --- | ---: | ---: | ---: | ---: |
| 文章 | 1.793 → 1.793 | 2.009 → 1.219 | 2.134 → 0.967 | 2.21倍 |
| 混合 | 2.847 → 2.884 | 3.097 → 1.969 | 3.417 → 1.394 | 2.45倍 |
| 高エントロピー | 9.150 → 9.169 | 9.971 → 5.698 | 9.953 → 3.608 | 2.76倍 |

1CPUでは補助workerを起動しません。1CPUでの小さな差は、同じ逐次処理の実行順・測定の揺れを切り分けていません。

4CPUでの8frame合計の総CPUは、文章2.431→3.038ms、混合3.987→4.494ms、高エントロピー10.766→12.013msでした。**待ち時間は短くなりますが、総CPUは約12〜25%増えます。** CPUが既に埋まっている場合の処理量増加を保証する値ではありません。

## 不採用にしたHuffman内の並列化

最初に、単一ブロックの4本のHuffman符号列を2workerへ分けました。作業表の追加割当と同期が増え、単一展開の改善が小さく、同時展開は遅くなったため削除しました。初期の`-test.cpu`だけの試行を残し、採用値は環境変数も固定して再測定しています。

## 検証と未確認範囲

store・app・evidence・disclosure・zstd圧縮/展開の通常試験、store・zstd圧縮/展開のraceとvet、全製品のCGO無効ビルド、設計検査が成功しました。packのfuzzは30秒指定で1,129実行し、成功しました。実行結果は全記録JSONの`validation`に保存しています。1/2/4CPU・8同時要求の復元一致、ブロック境界をまたぐ範囲と空範囲、全ブロックの保存CRC破損拒否、補助枠が埋まった状態での継続処理、全worker終了待ち、エラー順序を回帰試験に含めています。

実HTTP、ブラウザ、実ディスク、512MiB等のメモリ制限、長時間継続負荷、稼働ホストの性能は今回測定していません。pack読取りの短縮を投稿全体の処理量や復旧時間の保証には使いません。
