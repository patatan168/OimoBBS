# 大きい高エントロピーDATの追加圧縮

2026-11-01。比較元は`0cd506b`。435,955byteの合成DATで、**保存サイズ176,639→176,493byte（0.083%減）、圧縮時間10.47%・総CPU5.84%減**を確認しました。同一バイナリでの展開も時間0.57%・CPU0.75%減でした。サイズ削減は小さい結果です。[入力hash・全標本・採否判定](zstd-entropy-20261101.json)を保存しています。

## 性能の採用条件

圧縮後byteの削減率に対し、処理時間・総CPUの増加率がそれを超える変更を採用しません。圧縮はCRC付き保存処理、展開はCRC付き`DecodePackChunk`で測ります。前後でframeが変わるデータは、同じ製品decoderを同一実行ファイル内で比較します。

広い範囲へ変更した試作では、512KiBのhex DATが約0.003%小さくなる一方、展開CPUが約3.85%増える標本がありました。この版は不採用です。保存level 9の4byte探索候補に適用を限定し、従来の適応幅・7byte候補を残しました。

最終版の11入力では1入力が小さく、残りはframe自体がbyte同一でした。変更があるframeの圧縮・展開は時間もCPUも減っています。残り10入力は製品decoderも入力frameも同一です。別バイナリでの展開の生標本には小さい増減があるため、これを展開高速化の根拠にはしていません。すべての入力・稼働負荷に対する無条件の速度保証ではありません。

## 実装

先頭8KiBの既存sampleから、残ったliteralの推定が3.5〜5bit、literalがsampleの50〜96.875%となるblockを対象にします。保存用の自動精度9・4byte探索・16KiB以上のblockだけで、短い参照の固定推定費用を14bitへ変更し、literal区間の探索間隔を8byte単位で広げて最大32にします。推定費用が5bitを超える文字は引き続き飛ばしません。

通常方針は固定推定費用12bit、repeatは7bit、探索間隔は16byte単位・最大16です。HTTP、保存1/6、文字種が広いデータ、単純な繰返し、適応幅・7byte探索候補は通常方針を維持します。符号化形式・reader要件・最大2worker・8MiBの作業予約は変更していません。HTTPの出力byteと`-zstd-v13` ETagも維持します。

Go1.27.3、AMD Ryzen 5 5500U、`GOMAXPROCS=2`、`taskset -c 10,11`。比較元は変更した符号化ファイルをGit上の比較元へ差し替えるGo overlayで構築し、同じfixture生成器とbenchmarkを使いました。入力名は固定順です。前→後→後→前で500ms×2回、各版4標本の中央値を比較しています。

圧縮と展開の準備、入力生成、初回の復号照合は計時外です。毎回の圧縮・専有出力・保存CRCを計時し、圧縮済みcacheは使いません。展開は1回ごとの専有出力・CRC検査を含みます。計時中に自分の他のbuildや試験は重ねていません。共有ホストでCPUを排他的には確保していません。

元の1000レスDATと、128〜512KiBの別サイズ・別seed・hex/区切り付きhex/Base64/ASCIIを使いました。新しいfixtureはASCIIの完結したDAT行を生成し、稼働データを読みません。Base64やASCIIのように文字種が広いデータのサイズは据え置きです。圧縮時間・CPU差は圧縮処理だけで、全HTTPや投稿全体の速度改善率ではありません。

変更frameの展開は同じバイナリ内でbefore/afterの順序を反転させ、1秒×3回・4プロセス、各12標本で比較しました。経過時間は984.99→979.34µs、総CPUは1014.81→1007.21µsでした。確保量は両方442,368byte・1 allocationです。

## メモリと互換性

`Encoder`の固定サイズは356,944→356,976byteで、blockごとの費用・探索間隔を保持する32byteが増えます。新しい探索表・常駐cache・workerは追加していません。

beforeのプロセス最大RSSは[27828, 30020]KiB、中央値28.25MiBでした。
afterのプロセス最大RSSは[30084, 29896]KiB、中央値29.29MiBでした。

RSSはfixtureとGo runtime・GCを含む各版2プロセスの観測値で、稼働BBSの増分やピークの保証ではありません。

公開本文25件・制御入力3件・大DAT11件の156組について、サイズ非増加と入力の非変更を検査しました。新旧312frameを独立Go decoder・製品decoder・libzstdで照合し、保存234frameは旧v1.0.3製品decoderでも読めました。固定108frameの回帰試験はHTTP/保存1・6のbyte一致と、保存9のサイズ非増加・独立復号を維持します。

通常・関連race・HTTP TLS・vet・生成資産付き静的buildが成功しました。独立復号・保存往復・破損frameのfuzzは各20秒指定で合計33,716件が成功し、保存往復には新しい方針を使うseedを追加しています。全bootstrap試験、実機、WAN、稼働ピーク負荷・512MiB負荷は実施していません。

符号表の長さ制限、補助辞書、参照費用と探索間隔の別条件も比較し、採用しないソース・生標本を`var/measurements/zstd-entropy-20261101-094014/`に保持しています。長さ制限の試作では[Package-Mergeの原論文](https://www.ics.uci.edu/~dan/pubs/LenLimHuff.pdf)も参照しましたが、製品には追加していません。稼働反映は別の配備記録で扱います。
