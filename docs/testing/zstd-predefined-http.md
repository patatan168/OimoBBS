# HTTPの定義済みFSE表

2026-10-31。比較元は`4e93768`です。32KiB以下の配信本文で、標準の定義済みFSE表も比較するようにしました。**固定した17本文のうち8件が小さくなり、残りは同じサイズでした。追加削減は最大6.7%です。** 17件を各1回足した圧縮サイズは22,586→22,509byte、77byte（0.34%）減で、通信量全体を重み付けした改善率ではありません。大きいHTMLと保存出力の追加削減はありません。[全標本・本文hash・不採用案](zstd-predefined-http.json)を記録しています。稼働環境には反映していません。

## 変更

これまでは、参照列のliteral長・offset・参照長について、単一記号ならRLE表、それ以外なら頻度に合わせて生成した動的表を送っていました。短い列では動的表のヘッダーが符号列と同程度の大きさになることがあります。

今回、[RFC 8878の定義済み分布](https://www.rfc-editor.org/rfc/rfc8878.html#section-3.1.1.3.2.2)から表を起動時に構築します。本文ごとの初期状態・全遷移・ヘッダーのbit数を比較し、小さいものを選びます。定義済み表を使う列には表ヘッダーが不要です。動的表の比較では、既知の最良値以上になった候補の計算を打ち切ります。

適用先は従来からFSE表を保持していた32KiB以下の配信本文です。保存用の候補・大きい配信本文の表選択・参照探索は維持します。共有の定義済み表は構築後に変更せず、要求内のworkerやworkerごとの作業領域を増やしません。

独自復号器も定義済み表を読めるようにしました。低頻度記号を表の末尾へ置き、全状態の遷移が表内に収まることを検証します。展開長・履歴offset・bit不足・余りbit・frame末尾の検査は維持します。定義済みoffset表のcode21〜28は1MiB窓を必ず超えるため、追加bitを読む前に拒否します。動的FSE表の16bit先読み対策は、動的なML表にだけ適用します。

HTTPの強いETagは`-zstd-v11`へ更新しました。旧v10からの200、新表現の304、無圧縮DAT差分の206をローカルTLS試験で確認しています。

## 不採用案
