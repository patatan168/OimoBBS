# 小さいHTTP本文のZstandard圧縮

2026-10-31。比較元は`a552f19`。公開検証環境から取得済みのHTML・DAT・CSS・JS等17本文を変更せず比較しました。**今回の標本では圧縮対象のサイズを増やさず、圧縮時間の中央値も短縮しました。** 全入力での時間上限や、gzipより小さくなることを保証する結果ではありません。[全標本と入力hash](zstd-small-http.json)を保存しています。稼働環境には反映していません。

## 変更

- FSEの逆引き表を「記号数×状態数」から「状態数」へ縮めました。正規化頻度の境界から出力bit幅を計算し、同じ遷移先を繰り返し埋める処理を削減します。
- Huffman表のASCII範囲もFSEで圧縮し、直接表より小さいときだけ採用します。128〜255byteのliteralにもHuffmanを試し、全体が小さくならなければrawへ戻します。
- 512byte〜32KiBの配信本文に限り、3byteの一致候補を一つ追加しました。探索用の領域は32KiBです。大本文・保存では追加探索と初期化を行いません。
- 配信Zstandardの強いETagは`-zstd-v9`へ更新しました。保存用復号器が受け付ける形式の範囲を維持し、保存形式のreader要件は変更していません。静的資産の検証子は圧縮結果のhashから生成します。

形式の根拠は[RFC 8878のFSE](https://www.rfc-editor.org/rfc/rfc8878.html#section-4.1)と[Huffman表](https://www.rfc-editor.org/rfc/rfc8878.html#section-4.2.1)です。

## 同じ入力での比較

Go1.27.3、AMD Ryzen 5 5500U、`GOMAXPROCS=2`。単一encoderを再利用し、各操作で圧縮を実行します。圧縮済みキャッシュは使いません。返却配列の確保とGCを含み、入力読取り・圧縮器の初期準備・復号確認は計時外です。前→後、後→前の順で各200msを3回、計6標本の中央値を比較しました。

| 入力 | zstd byte 前→後 | 追加削減 | 圧縮時間 µs 前→後 |
| --- | ---: | ---: | ---: |
| トップHTML | 1,994→1,943 | 2.6% | 130.4→98.9 |
| 板HTML | 2,210→2,153 | 2.6% | 133.9→103.5 |
| スレッドHTML | 4,185→4,110 | 1.8% | 197.7→175.7 |
| DAT全文 | 1,186→1,169 | 1.4% | 106.1→65.5 |
| SETTING.TXT | 322→303 | 5.9% | 48.7→32.8 |
| 共通CSS | 2,538→2,498 | 1.6% | 176.6→155.4 |
| 公開CSS | 1,187→1,146 | 3.5% | 114.1→74.8 |
| スレッドCSS | 610→580 | 4.9% | 71.8→45.0 |
| 共通JS | 358→329 | 8.1% | 43.6→30.6 |

圧縮対象となる200byte以上の16本文では、14件が小さくなり、DATの一つとSVGは同じ長さでした。時間の中央値は全16件で約9〜43%短縮しました。82byteのsubject.txtは実HTTPでは圧縮しません。参考として強制圧縮した単体値は91byteのまま、約4.1→4.2µsでした。

大きい合成DATのtext/mixed/entropyも、それぞれ12,208→12,191、31,049→31,016、177,302→177,198byteで、時間の中央値は約4〜8%短縮しました。追加探索を大本文にも適用した試作は、entropyで約83%、mixedで約26%遅くなったため不採用です。

小さい入力では改善後もgzipのほうが小さい例があります。上表のトップHTMLはgzipが1,909byte、DAT全文は1,138byte、共通JSは307byteでした。これらは前回HTTPで取得したgzip本文で、今回gzipの速度を比較したものではありません。スレッドHTMLのgzipは4,642byteで、改善後zstdのほうが小さい結果です。

## 検証と範囲

17本文を独立Go復号器とlibzstdで展開し、元byteとの一致を確認しました。128〜255byteのliteral、ASCII表の圧縮・直接形式、511/512/513byteと32KiB前後の探索切替境界を検査しています。実TLSの試験で旧v8条件からの200、新v9の304、無圧縮のDAT差分206も確認しました。

圧縮・復号・compat・静的資産生成・webuiのrace、保存の通常試験、bootstrapの関連試験が成功しました。圧縮・保存プロファイル往復・破損frame復号のfuzzを各20秒指定で実行し、それぞれ2,977・2,826・7,536件を通過しました。全製品・ツールのvetとCGO無効ビルド、静的資産の一致、文書・fixture検査も成功しました。全bootstrap試験・実機・変更後の公開URL・本番負荷の検証ではありません。生成済み静的資産は再生成しましたが、稼働中のコンテナは置換していません。

再実行には、取得本文の`<label>-identity.body`と`results.json`を同じディレクトリへ用意します。今回の生データ・新旧試験バイナリ・不採用試行は`var/zstd-http-20261031/`、取得本文は`var/live-reading-compression-20261031T043707Z/`に保存しています。
