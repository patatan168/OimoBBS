# WAF

管理画面の「WAF」または「運用設定」内のリンクから、要求の追加検査をON/OFFできます。初期状態はOFFです。サイト管理者が再認証して保存すると、サーバーの再起動なしで反映します。保存した状態は再起動後も維持します。

## 読む順序

| 確認したいこと | 参照先 |
| --- | --- |
| ON/OFFと制限の組合せ | [スイッチの関係](#スイッチの関係) |
| Host・ヘッダー・サイズなどの遮断条件 | [検査と遮断](#検査と遮断) |
| 通常要求・投稿・検索の頻度と同時処理 | [大量アクセスの制限](#大量アクセスの制限) |
| 投稿本文・Cookieなどの検査範囲 | [通常通信との境界](#通常通信との境界) |
| API・保存条件・旧形式 | [設定と記録](#設定と記録) |

## 管理画面の見方

画面上部に有効状態・遮断件数・処理中の要求数を表示します。設定は「動作」「通常アクセスの上限」「処理別の追加上限」に分けています。

同一回線と全体の値を並べて確認し、検索・投稿の上限は必要なときに開いて編集します。折りたたんでも値は保存対象に含まれます。削除依頼・管理認証の固定上限は参照のみです。保存には再認証・CSRF・版比較が必要です。

稼働状況は公開側と管理側を分け、処理別の集計は詳細を開いて確認します。JavaScriptを無効にしても項目の開閉とフォーム保存を利用できます。

## スイッチの関係

| WAF | 大量アクセス制限 | 同一ネットワークの制限 | 動作 |
| --- | --- | --- | --- |
| OFF | 任意 | 任意 | WAFの追加検査・大量アクセス制限を停止 |
| ON | OFF | 任意 | URL・ヘッダー等の追加検査だけを適用 |
| ON | ON | OFF | 追加検査と全体枠・処理別全体枠を適用 |
| ON | ON | ON | 上記に回線別の枠を追加 |

OFFにしても保存値は維持します。WAF以外の認証・投稿規制・接続数・通信量・サイズの制限も引き続き適用します。

## 検査と遮断

公開HTTP受付と管理画面のHTTP受付で、本文を読んだりルートを処理したりする前に検査します。公開入口を利用する構成でも、保存サーバーの同じ検査を通ります。

| 対象 | 遮断条件 |
| --- | --- |
| メソッド | GET・HEAD・POST・PUT・PATCH・DELETE・OPTIONS以外 |
| パス | `.`・`..`による経路移動、制御文字、`.git`・`.svn`・`.hg`・`.ssh`・`.aws`・`.env`・`.env.*`・`.env~`・`.docker`・`.kube`・`.npmrc`・`.netrc`・`.htpasswd`・`.DS_Store`・`id_rsa`・`id_ed25519`・`wp-config.php`（末尾が`.`または`~`で続く退避名も含む）の探索 |
| パス・クエリ | `UNION SELECT`、`sleep()`・`pg_sleep()`・`benchmark()`・`WAITFOR DELAY`等の既知SQLパターン、script/iframe/object/embedタグ、javascriptスキーム、onerror/onload、区切りに続くcurl/wget/bash等の既知コマンドパターン |
| Host | WAF有効時は、公開用・管理用それぞれの設定済みHostとの照合を頻度枠より前に行う。転送ヘッダーで補正しない |
| ヘッダーの構文・量 | 値にNUL・CR・LF等の禁止制御文字またはDEL、User-Agent合計1KiB超、解析済みヘッダー128項目超。Cookie・Authorizationも構文と量だけを検査する |
| 宣言本文長 | 公開64KiB超、管理256KiB超、負の不正値、Content-Lengthの不正・矛盾。各処理のより小さい本文上限も維持する |
| ヘッダーの参照パターン | Cookie・Authorization以外の値にある`${jndi:`参照パターン。既知の`lower`・`upper`・`:-`による難読化を最大4段まで展開して照合 |
| 検査量 | エンコード済みパスとクエリの合計16KiB超、Cookie・Authorizationを含むヘッダーの名前と値の合計16KiB超、クエリ128項目超 |

### ヘッダー・Host・本文長の扱い

ヘッダーの横タブ（HTAB）と非ASCIIの値は許可します。禁止する制御文字の扱いは[HTTPのフィールド値の規則](https://www.rfc-editor.org/rfc/rfc9110.html#section-5.5)に従います。UAは複数の値や表記違いのヘッダーを合計して1KiBまでです。ヘッダーの同名繰返しもそれぞれ一項目として数えます。Host等、Goが専用フィールドへ分離した項目は、この件数に含めません。CookieやAuthorization内の攻撃パターンを解釈する処理は追加しません。

Hostは公開の `public.base_url`、管理の `admin.origin` に従います。設定済みの標準portの省略とASCIIの大文字小文字は従来通り扱い、開発用・トンネル用に設定したlocalhostやIPは利用できます。Hostの既存検査はWAFをOFFにしても継続します。

負のContent-Length、異なるContent-Lengthの重複、不正ヘッダー、ヘッダー受信量超過などは、Go標準のHTTPサーバーが先に400・431等で拒否する場合があります。WAFは構文解析後の要求を検査するため、標準パーサーが既に正規化した生のframingを再検査する仕組みではありません。受信ヘッダーの既存16KiB上限は維持します。

正規のchunked送信は許可し、本文を扱う各処理では受信中もサイズ上限を適用します。宣言長を省略して本文上限を回避することはできません。未受信本文のあるHTTP/1要求をWAFで拒否した場合は接続を閉じ、本文の送信や100 Continueを待ちません。HTTP/2では他のstreamのために接続を閉じません。

### パス・クエリの扱い

クエリは生の `&` で区切った項目を最大128件まで受け付けます。同名項目と空項目もそれぞれ数え、129件以上はクエリを分解する前に拒否します。値中の `%26` は区切りとして数えません。クエリがない要求では項目数の走査を省きます。検索語 `q` の文字列検査を除外していても、この件数・サイズの制限は適用します。

この上限はクエリ解析用のmap・値配列の確保を抑えるものです。HTTPサーバーが要求行やヘッダーを受信するためのメモリとは別です。本文を読み込む処理や外部照会は追加しません。

パス・クエリ値は最大3回percent復号して照合します。クエリの不正なエンコードも拒否します。一致した要求には本文やルートの処理へ進まず、`Cache-Control: no-store`付きのHTTP 403を返します。規則名や検出文字列は応答に含めません。

SQLの`/* ... */`コメントを含む値だけは、コメントを空白に置き換えて追加照合します。`UNION/**/SELECT`などの区切り回避が対象で、SQL文法全体の解析や、あらゆる難読化の解除は行いません。通常パスとクエリでは、必要な区切り文字や先頭コマンド候補の有無で正規表現を省き、難読化されたヘッダーの追加処理も`${`がある値に限定します。

管理画面のCSS/JS取得URLに符号化されている表示元ページも、復号後に同じWAF検査を通します。資産取得を使って表示元の検査を省くことはできません。認証用のQR画像など、HTML以外の処理を表示元として実行しません。

## 大量アクセスの制限

管理画面ではWAF全体と別に「大量アクセス制限」をON/OFFできます。WAF全体がONの場合にだけ適用します。既存のWAF設定から更新した場合も、WAF全体のON/OFFは維持し、大量アクセス制限には次の緩めの初期値を使います。実際の処理能力を保証する値ではありません。

「同一ネットワークの制限」は独立してON/OFFできます。OFFでは下表と処理別追加枠の回線別上限を適用せず、全体の頻度・検索・投稿・管理処理の上限と攻撃検査は継続します。数値は保存して維持するため、再有効化時に再入力は不要です。WAF全体または大量アクセス制限がOFFの場合は、このスイッチがONでも回線別の制限は停止しています。管理画面では、停止中の上限欄を薄く表示して編集不可にし、ONへ戻すと再び編集できます。無効な欄の値も保存時に保持します。JavaScriptが無効な場合は通常のフォームで編集できます。

| 枠 | 毎秒の補充 | 瞬間的に許可する件数 | 同時処理 |
| --- | ---: | ---: | ---: |
| 同一回線 | 60件 | 180件 | 32件 |
| 全体 | 300件 | 600件 | 128件 |
| 同一回線の検索 | 2件 | 10件 | 全体の検索枠を共用 |
| 全体の検索 | 12件 | 24件 | 4件 |

各値は管理画面から変更でき、保存後すぐに反映します。瞬間枠は満杯から開始し、要求ごとに1件分を使い、毎秒枠の速度で連続して補充します。たとえば同一回線の瞬間180件を使い切った後も、毎秒60件の速度で回復します。設定変更やON/OFFで消費量や処理中の枠をリセットしません。再起動時はメモリ上の枠を初期化します。

同一回線はIPv4の1アドレス、IPv6の/64単位です。同じNAT・VPN出口を共有する利用者は枠も共有します。共有回線で制限しすぎる場合は、回線別の枠を増やすか「同一ネットワークの制限」をOFFにできます。公開入口経由では、mTLS・信頼する中継元・申告情報の検証後の利用者IPを使い、任意のX-Forwarded-Forを信用しません。

### 高負荷処理の追加枠

WAFと大量アクセス制限の両方がONのとき、以下の処理は通常枠と処理別の追加枠を使います。同じ行の入口は回線別・全体とも枠を共有します。通常のDAT・subject取得の上限は変えません。

| 処理 | 入口 | 同一回線（毎秒 / 瞬間 / 同時） | 全体（毎秒 / 瞬間 / 同時） |
| --- | --- | ---: | ---: |
| 投稿 | `POST /test/bbs.cgi`、`POST /web/post` | 10 / 30 / 8 | 60 / 120 / 32 |
| 削除依頼・照会 | `/reports`、`/reports/lookup`（フォーム表示も含む） | 2 / 6 / 2 | 8 / 16 / 4 |
| 管理ログイン・再認証 | 管理受付の`POST /login`、`POST /reauth`、`POST /api/v1/reauth` | 1 / 3 / 1 | 4 / 8 / 2 |

管理パスを公開URLに組み込む構成では、その接頭辞を除いて分類します。管理ログイン画面のGETは通常枠です。表の投稿枠は既定値で、管理画面の「投稿の追加上限」から回線別・全体の毎秒・瞬間・同時処理を変更できます。規約同意の確認と送信は別要求として数えます。専ブラ・Webともに同じ規約へ同意済みなら、投稿ごとの確認往復を省略します。投稿枠と通常枠の小さい方を適用し、投稿枠だけを上げても通常枠を超えません。削除依頼・照会と管理ログイン・再認証の追加枠は固定です。従来の投稿間隔、削除依頼の制限、認証試行回数・パスワード照合worker制限も引き続き適用します。

通常枠と追加枠は同じロックで確認し、どちらかの拒否でトークンを消費することはありません。通常閲覧だけの回線には処理別の状態領域を確保しません。追加枠も設定変更・ON/OFFで消費量や実行数をリセットせず、拒否の連続で待ち時間を延長しません。処理別全体枠で拒否する新規回線は記憶しません。APIの`public_traffic`・`admin_traffic`には`posting`・`reports`・`authentication`ごとの`active`・`rate_limited`・`overloaded`も返します。これらの拒否件数は既存の合計にも含めます。

Hostと宣言本文長の軽量な拒否を先に行い、文字列検査より先に頻度・同時処理枠を確認します。通常要求の枠にはGET、HEAD、Range、304応答、投稿、静的ファイルを含めます。`/search`は通常枠と検索専用枠の両方を使います。利用者別の上限超過にはHTTP 429、全体の混雑にはHTTP 503を返し、どちらも`Retry-After`と`Cache-Control: no-store`を付けます。拒否では本文やルートを処理せず、トークンを消費しません。

永久BANや、拒否するたび延長される停止期間は設けません。同時処理枠は応答処理終了時に解放します。[429とRetry-Afterの仕様](https://www.rfc-editor.org/rfc/rfc6585.html#section-4)に従います。

公開側と管理側の枠は別々です。公開側が上限に達しても管理側の枠は消費しません。ただしCPU・通信帯域などの物理資源は共有します。記憶する回線は各側で最大4096件とし、実行中でなく2分以上使われていないものを定期的に除外します。回線別制限がONで、上限に達して新しい回線を記憶できない場合は503を返します。回線別制限がOFFの間は新しい回線を記憶せず、この記憶数を理由に拒否しません。全体の頻度・同時処理枠で既に拒否する新しい回線は記憶しません。頻度・同時処理・検索の集計件数は管理画面で確認でき、再起動で0に戻ります。

保存値は整合性と資源上限を検証します。全体枠は同一回線枠以上、瞬間枠は毎秒枠以上、検索枠は通常枠以下にしてください。入力可能な最大値まで増やしても、既存の接続数・HTTP/2・送信帯域・処理枠などの上限は別に適用します。

この制限はアプリ内の処理とメモリの保護です。TLS受付以前の負荷、回線帯域を埋める大量通信、上流回線での遮断は扱いません。そうしたDDoSには公開入口や回線業者側の対策が必要です。

[不正フォームを反復するBotの自動停止](features/abuse.md#不正フォームを反復するbotの自動停止)は、検証済みCookie単位の投稿対策です。WAFのON/OFFに関係なく動作し、管理画面の「掲示板全体の荒らし対策」で調整します。

## 通常通信との境界

投稿本文、フォーム本文、JSON本文は読み取りません。Cookieと認証情報はHTTPヘッダーとしての構文・量だけを照合し、攻撃パターンの文字列検査には含めません。`/search`の検索語`q`も除外します。これらの入力には従来の投稿検査・出力エスケープ・認証・CSRF・回線制限・要求サイズ制限を適用します。技術的な説明や攻撃コードの引用を投稿しただけでWAFが遮断することはありません。

この実装は掲示板向けの限定的な追加検査です。OWASP CRS全体の実装ではなく、あらゆるSQL注入・XSS・コマンド注入や本文内の攻撃を検出するものではありません。TLS以前の通信や大規模な通信攻撃の防止も対象外です。[CRSの誤検知と入力ごとの除外](https://coreruleset.org/docs/2-how-crs-works/2-3-false-positives-and-tuning/)も参照してください。

OFFにするとWAFによる追加検査と大量アクセス制限を停止します。既存の公開入口の検査、認証、投稿規制、回線制限、通信量・同時処理・サイズの上限は解除しません。

## 設定と記録

### 管理API

`GET /api/v1/waf` で取得し、`POST /api/v1/waf` で保存します。公開パス構成では、設定済みの管理パスを先頭に付けます。

| JSONの場所 | 指定する項目 |
| --- | --- |
| 最上位 | `enabled`、`traffic` |
| `traffic` のスイッチ | `enabled`、`client_enabled`（回線別制限） |
| `traffic` の通常枠 | `client_rate`、`client_burst`、`global_rate`、`global_burst`、`client_concurrent`、`global_concurrent` |
| `traffic` の検索枠 | `search_rate`、`search_burst`、`search_global_rate`、`search_global_burst`、`search_concurrent` |
| `traffic.posting` の投稿枠 | `client_rate`、`client_burst`、`global_rate`、`global_burst`、`client_concurrent`、`global_concurrent` |

現在の形式では通常枠・検索枠の各項目を指定します。投稿枠を含める場合は6項目すべてが必須です。未知キー、部分的な欠落、重複、null、文字列の真偽値、不正な数値、整合しない上限は拒否します。

### 保存条件

サイト管理者権限、直近の再認証、CSRF、`If-Match`、`Idempotency-Key`が必要です。同じキーの同じ再送は前の結果を返し、別内容への使い回しや古い設定版による保存は拒否します。

設定と操作者の監査記録を保存してから、稼働中の状態を切り替えます。設定変更やON/OFFで、消費済みの枠や処理中の件数をリセットしません。

### 旧形式の読み込みと保存形式

| 旧形式 | 読み込み・更新時の扱い |
| --- | --- |
| 投稿枠のない保存値 | 従来の既定投稿枠を使用 |
| 投稿枠を省いたAPI要求 | 稼働中の投稿設定を維持 |
| `client_enabled` のない保存値 | 回線別制限はON |
| `client_enabled` を省いたAPI要求 | 稼働中のON/OFFを維持 |
| `{"enabled":true}` または `{"enabled":false}` だけのAPI要求 | WAFのON/OFFだけを変更し、大量アクセス設定を維持 |

回線別スイッチを保存した後は、OFFの場合もreader91以降が必要です。スイッチのないreader88の投稿枠、投稿枠のないreader87の保存値、reader86のON/OFFだけの保存値も読み込めます。

### 集計とログ

遮断件数は現在のプロセス内だけで集計し、再起動で0に戻ります。WAF専用のIP、Cookie、本文、攻撃文字列の保存は追加しません。通常HTTPログと管理操作の監査は、それぞれの設定・保持期限に従います。


## 保存済みの検出・拒否

管理画面の「WAF検出・拒否ログ」で過去7日間の理由別件数と検出対象を確認できます。類似文・埋め立て・掲示板全体の投稿規制も同じ画面に表示します。保存・集約の上限とNGワード登録は[投稿規制・荒らし対策](features/abuse.md#waf検出拒否ログ)を参照してください。
