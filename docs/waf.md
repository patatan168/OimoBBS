# WAF

管理画面の「WAF」または「運用設定」内のリンクから、要求の追加検査をON/OFFできます。初期状態はOFFです。サイト管理者がパスワードを再確認した後に保存すると、サーバーの再起動なしで反映します。保存した状態は再起動後も維持します。

## 検査と遮断

公開HTTP受付と管理画面のHTTP受付で、本文を読んだりルートを処理したりする前に検査します。公開入口を利用する構成でも、保存サーバーの同じ検査を通ります。

| 対象 | 遮断条件 |
| --- | --- |
| メソッド | GET・HEAD・POST・PUT・PATCH・DELETE・OPTIONS以外 |
| パス | `.`・`..`による経路移動、制御文字、`.git`・`.svn`・`.hg`・`.ssh`・`.aws`・`.env`・`.env.*`の探索 |
| パス・クエリ | `UNION SELECT`、`sleep()`等の既知SQLパターン、script/iframeタグ、javascriptスキーム、onerror/onload、区切りに続くcurl/wget/bash等の既知コマンドパターン |
| ヘッダー | Cookie・Authorization以外の値にある`${jndi:`参照パターン |
| 検査量 | エンコード済みパスとクエリの合計16KiB超、検査するヘッダーの合計16KiB超 |

パス・クエリ値は最大3回percent復号して照合します。クエリの不正なエンコードも拒否します。一致した要求には本文やルートの処理へ進まず、`Cache-Control: no-store`付きのHTTP 403を返します。規則名や検出文字列は応答に含めません。

## 大量アクセスの制限

管理画面ではWAF全体と別に「大量アクセス制限」をON/OFFできます。WAF全体がONの場合にだけ適用します。既存のWAF設定から更新した場合も、WAF全体のON/OFFは維持し、大量アクセス制限には次の緩めの初期値を使います。実際の処理能力を保証する値ではありません。

| 枠 | 毎秒の補充 | 瞬間的に許可する件数 | 同時処理 |
| --- | ---: | ---: | ---: |
| 同一回線 | 60件 | 180件 | 32件 |
| 全体 | 300件 | 600件 | 128件 |
| 同一回線の検索 | 2件 | 10件 | 全体の検索枠を共用 |
| 全体の検索 | 12件 | 24件 | 4件 |

各値は管理画面から変更でき、保存後すぐに反映します。瞬間枠は満杯から開始し、要求ごとに1件分を使い、毎秒枠の速度で連続して補充します。たとえば同一回線の瞬間180件を使い切った後も、毎秒60件の速度で回復します。設定変更やON/OFFで消費量や処理中の枠をリセットしません。再起動時はメモリ上の枠を初期化します。

同一回線はIPv4の1アドレス、IPv6の/64単位です。同じNAT・VPN出口を共有する利用者は枠も共有します。誤検知がある場合は同一回線の枠を増やしてください。公開入口経由では、mTLS・信頼する中継元・申告情報の検証後の利用者IPを使い、任意のX-Forwarded-Forを信用しません。

制限枠は文字列検査より先に確認します。通常要求の枠にはGET、HEAD、Range、304応答、投稿、静的ファイルを含めます。`/search`は通常枠と検索専用枠の両方を使います。利用者別の上限超過にはHTTP 429、全体の混雑にはHTTP 503を返し、どちらも`Retry-After`と`Cache-Control: no-store`を付けます。拒否では本文やルートを処理せず、トークンを消費しません。永久BANや、拒否するたび延長される停止期間は設けません。同時処理枠は応答処理終了時に解放します。[429とRetry-Afterの仕様](https://www.rfc-editor.org/rfc/rfc6585.html#section-4)に従います。

公開側と管理側の枠は別々です。公開側が上限に達しても管理側の枠は消費しません。ただしCPU・通信帯域などの物理資源は共有します。記憶する回線は各側で最大4096件とし、実行中でなく2分以上使われていないものを定期的に除外します。上限に達して新しい回線を記憶できない場合は503を返します。全体の頻度・同時処理枠で既に拒否する新しい回線は記憶しません。頻度・同時処理・検索の集計件数は管理画面で確認でき、再起動で0に戻ります。

保存値は整合性と資源上限を検証します。全体枠は同一回線枠以上、瞬間枠は毎秒枠以上、検索枠は通常枠以下にしてください。入力可能な最大値まで増やしても、既存の接続数・HTTP/2・送信帯域・処理枠などの上限は別に適用します。

この制限はアプリ内の処理とメモリの保護です。TLS受付以前の負荷、回線帯域を埋める大量通信、上流回線での遮断は扱いません。そうしたDDoSには公開入口や回線業者側の対策が必要です。

## 通常通信との境界

投稿本文、フォーム本文、JSON本文、Cookie、認証情報はWAFの文字列検査に含めません。`/search`の検索語`q`も除外します。これらの入力には従来の投稿検査・出力エスケープ・認証・CSRF・回線制限・要求サイズ制限を適用します。技術的な説明や攻撃コードの引用を投稿しただけでWAFが遮断することはありません。

この実装は掲示板向けの限定的な追加検査です。OWASP CRS全体の実装ではなく、あらゆるSQL注入・XSS・コマンド注入や本文内の攻撃を検出するものではありません。TLS以前の通信や大規模な通信攻撃の防止も対象外です。[CRSの誤検知と入力ごとの除外](https://coreruleset.org/docs/2-how-crs-works/2-3-false-positives-and-tuning/)も参照してください。

OFFにするとWAFによる追加検査と大量アクセス制限を停止します。既存の公開入口の検査、認証、投稿規制、回線制限、通信量・同時処理・サイズの上限は解除しません。

## 設定と記録

- 管理用APIは`GET /api/v1/waf`と`POST /api/v1/waf`です。公開パス構成では設定済みの管理パスを前に付けます。
- 保存本文は`enabled`と`traffic`です。`traffic`には`enabled`、`client_rate`、`client_burst`、`global_rate`、`global_burst`、`client_concurrent`、`global_concurrent`、`search_rate`、`search_burst`、`search_global_rate`、`search_global_burst`、`search_concurrent`をすべて指定します。未知キー、部分的な欠落、重複、null、文字列の真偽値、不正な数値や整合しない上限は拒否します。旧形式の`{"enabled":true}`または`{"enabled":false}`によるAPI切り替えも受け付け、現在の大量アクセス設定を維持します。
- 保存にはサイト管理者権限、直近の再認証、CSRF、`If-Match`、`Idempotency-Key`が必要です。同じキーの同じ再送は前の結果を返し、別内容への使い回しや古い設定版による保存は拒否します。
- 設定と操作者の監査記録を保存完了してから稼働中の状態を切り替えます。新形式で保存した後は、OFFの場合もreader87以降が必要です。旧reader86のON/OFFだけの保存形式も読み込めます。
- 遮断件数は現在のプロセス内だけで集計し、再起動で0に戻ります。WAF専用のIP、Cookie、本文、攻撃文字列の保存は追加しません。既存の通常HTTPログと管理操作の監査は、それぞれの設定・保存期限に従います。
